除 71 项 prompts 与 prompt_order，`extensions.tavern_helper.scripts` 还包含“照本宣科”和“漫画台 v1.1”。后者包含 JSON 解析、生图参数编译、画风库读取，以及 BUNDLED_ASSETS 中的资料表和剧情推进模板。

此前审计中“原版外部脚本未提供”的判断不成立，已更正。

## 输入与前置流程

漫画预设通过 plot_bridge 接收 user_input、lookup、scene、beat、act；将已定案台本完整转译为漫画，保持事件因果、顺序和发言人。

附带剧情推进模板有三个启用任务：检索与召回 → 剧情推进 → 正文与伏笔。最后任务生成 200～600 字的演出段落，要求具体可见动作、明确人物姓名、初始位置、服装变化、持有物和结束状态；台词建议每句不超过 30 字。它处理的是上游台本创作，不等同于 SDT 对任意已有楼层的前情分析。

教程明确标注导入剧情推进预设为可选。模板内任务 enabled=true 只证明模板内容，不证明用户宿主已导入并在使用。不能据此给 SDT 强加三轮请求或截断已有楼层为 600 字。

## 漫画规划与分镜

原版先输出整轮角色 DNA、状态变化、连续场景和逐页剧情分配；再对每一页输出 comic_plan 与 image JSON。逐页规划明确页面形态、格数、阅读路径、主格位置与大小、辅助格位置与大小；逐格明确景别、定格时刻、动作、持物、空间关系、文字来源与归属。

通用文法明确要求主格大致面积、辅助格宽窄高低及排列，并写有“每个格子必须不同大小”。位置说明要在页面、环境及人物提示词中一致；P1/P2 编号不能替代空间描述。没有要求一律用三格或四格横条，也没有强制每页空镜开场。

原文件保存的组合同时启用通用文法和少年热血，后者另外要求半页以上主格与至少两格斜切；固定页数实际为六页。用户当前选择通用文法与 SDT 自适应页数，比较时应区分条件。不能把强制六页、斜切当作通用修复。

适配重点是保留最终可执行的布局描述，不要求恢复冗长逐句来源账本、硬校验或模型重试。

## 人物资料与逐格出场

原版模板有角色 DNA 表，按姓名保存身份、稳定外貌、开场穿搭和差异特征；另有关键物品与场景资料表。未知不补，未确认变化保留原文，不用楼末穿搭覆盖开场穿搭。

原脚本 resolveChars 返回空 entries；assemblePrompt 直接使用文本模型提供的完整人物 positive/negative。没有在该生图编译路径中用 SDT 的七部位正则分类器重新装配外貌。逐格取可见子集、追踪画外仍成立的状态，由原版指令交给文本模型完成。

原版对原创姓名和精确年龄的绘图表达限制比用户要求严格；这些不能作为删除 SDT 长期记忆中姓名、国籍、年龄、身高的理由。适配应尊重用户明确的保存要求。

## 黑白模式

color_monochrome 要求文本模型对角色 DNA、人物槽、道具、场景统一灰阶转译，每页写黑白介质词，环境只保留光源方向和明暗。固定画风库由脚本读取并拼入 NAI 请求，不发送给文本模型。

这是生成阶段的整体转译，不是只对少数发色眼色执行正则替换。SDT 可保留长期资料的原色，但必须明确长期记忆与本次灰阶绘图表达的区别。

## 最终请求编译

parseV83ImageProtocol 将 page.base、page.non_character、各格 description/non_character 的视觉部分连接为 base；各非人物 Text 用空行连接到末尾一个 Text。当前插件的类似合并方式与原脚本一致，不能列为适配独有缺陷。

各格人物出场保留为独立 char_captions，正负词分别发送。同一角色在不同格出现可以有多个槽位。默认 auto 时 use_coords=false，中心点回退到 0.5 不等于把所有人物强制放到同一位置。

对白属于可见人物时，原版要求放在该人物 positive。实际样图中对白出现在全局 base 的问题，应先落实该归属，而不是擅自改变语言或新增双语删减规则。

横向跨页标记用于请求时交换宽高；开启智能跨页不代表每张图必须横向。
