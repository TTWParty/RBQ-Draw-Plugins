# 漫画模式与漫画工作台

插件 ID：`rbq-manga-mode`。入口：[manga-mode.js](../../plugins/manga-mode.js)。

版本：**1.9.33**，配套智能生图（SDT）**6.5.22**、角色工坊 **2.2.29**。更新漫画插件与 SDT 后刷新酒馆。宿主 **0.3.110** 增加每次生图请求的上下文传递；旧宿主兼容路径串行提交 SDT 生图。

## 1.9.33 / SDT 6.5.22：正文、页格规划与格内绘图分层试用

新增独立选项 **漫画 · 正文分层规划（试用 · V23格内指导）**（`v_manga_layered_v1`）。同一次模型请求依次组装三个模块：漫画基础规范负责数据结构、身份、状态与文字归属；正文漫画规划负责选材、分页、每页分格、阅读路径、定格与对白；V23 漫画适配模块把既定画面写成格内动作、接触对象、视线、环境和局部负词。第三层是专门整理的漫画指导，开启此选项后已自动绑定，无需再去普通 SDT 系统预设中选择 V23。

主链路支持按正文改编多页，手动描述同样允许多页；测试入口严格一页。工作台仍是单页任务，自动安排 1～5 格，指定格数与经典四格按任务执行；自动拟音遵循原开关，格位和景别分别写入 `position/shot`。已有页、单格和批量润色使用保留式编辑指令，明确 `[]` 继续清空文字，不能因润色重新选取整段正文。所有入口共用同一个构建器，JSON、工具调用与自定义 HTTP 各自保留原传输方式。

新组合去掉重复的前情摘要、分页指令和旧整页导演拼接。开启「同步预设风格至 LLM 思考」时，原支持注入的 SDT 入口只把预设名称、正面词和负面词作为 `stylePreset` 资料发送，不再把字面风格追加为系统指令；工作台和已有页润色没有新增隐式风格注入。外部提示词预设的最终生图拼接机制保持原样，它不等于逐格 V23 指导。

规划、对白方式、画风、画布和相关开关在请求开始时保存快照，等待期间切换设置作用于下一次请求。新响应在写入外貌记忆、灰阶缓存或工作台草稿前检查任务形状、页数、格数和非空 `page.base`；单页任务返回多页会保留完整错误输出，不能截取第一页掩盖越界。已有明确说话者引用归位及归属校验继续执行。旧组合及已存选择保留，不自动迁移默认值；旧缓存重绘不会重新运行新规划。

使用：更新两个插件并刷新酒馆，开启漫画模式，在 **正文漫画规划** 中选择 **正文分层规划**，对正文重新解析后生图。可以随时切回原选项；评估时固定正文、模型、画风、画布和对白方式，先检查页树是否完整，再检查成图。

验证：34 个漫画与 SDT 回归脚本共 **784 项检查通过**，其中新增分层专项 36 项，覆盖实际请求、两种对白、编译结果、编辑范围、设置快照与历史请求兼容。任务越界另有针对性的错误指引，避免把多页返回误说成没有页面数据。语法、版本清单及差异检查通过。测试使用中性剧情与模拟响应，**未调用真实模型或生图服务，分页遵循率和成图质量尚未验证**。模块、接口与后续评估方法见 [三层方案及实施记录](rbq-manga-three-layer-prompt-handoff-2026-10-06.md)。

## 1.9.30 / SDT 6.5.20：明确说话者引用与气泡归位

结构化人物气泡支持可选 `speaker_id`，共享提示和完整示例要求已知发言人填写与 `character_id` 相同的编号。推荐仍直接放入本人 `bubbles`。若模型误放到格级，但提供了同格唯一可见人物的明确编号，且该人物没有其他文字，解析器会按引用归回人物，保留原句、类型、位置、排版与源数组顺序。处理成功会显示归位说明，不再只报告层级错误。

正文解析、工作台新分镜/润色与 SDT 微调共用此处理。画外声仍需明示 `offscreen`；缺少编号不猜测，未知编号、同格重复身份、人物内编号不符或目标已有文字继续拒绝响应。失败保留搬运前的原始 JSON，并在记忆和缓存写入前结束。仅编译/重绘旧缓存不会自动搬移文字，也没有增加模型请求或自动重试。

更新两个插件并刷新酒馆后重新解析，旧响应不会自行补出编号。该引用解决的是字段归位，不能证明模型判定的说话者符合正文，也不保证生图模型精确画出文字与气泡位置。实现、接口和验证范围见 [明确说话者归位记录](rbq-manga-bubble-speaker-routing-2026-10-06.md)。

验证：33 个漫画与 SDT 回归脚本共 746 项检查通过，包括新增 31 项说话者归位测试；语法、版本/缓存地址清单与差异检查通过。未调用真实模型或生图服务。

## 1.9.29 / SDT 6.5.19：漫画 5.0 商业大师导演规划（Universal Director v5.0）

基于《全题材通用日漫与同人本单页导演白皮书 v5.0》全新构建，在「前情增强分析」中新增顶配选项 **漫画 5.0 · 商业大师导演规划（推荐 · v5.0白皮书标准）**（`v_manga_v5`）。

彻底解决当前模型生成的两大核心缺陷：
1. **彻底绝杀“无头尸体长出头”与严重残缺死伤回写**：斩首（headless/decapitated）、死亡或残躯角色，严禁复用人物卡固有外貌 base！首选下放到画格 `description` 或 `non_character` 作为环境静物呈现；若保留人物槽，强制 `state.base` 覆写为无头躯体，并在 `character.negative` 强制注入 `head, face, eyes, mouth, hair, facial features, portrait`，切断扩散模型对头部的暴力脑补。
2. **彻底解决“角色混乱与串色”的多角色接触熔接（Contact Fusion）**：双人互动（搏击、推倒、拥抱、壁咚、体位交缠）严禁各写各的站桩。由 `page.base` 统领全局互动矢量，支配方与受制方分别注入主动与被动姿态，局部坐标重叠紧贴。
3. **黄金主格（Hero Panel 45%~65%）绝对统治律**：打破平分均等 PPT 排版，确立单页绝对高潮主格，辅以 10%~25% 铺垫与反应格，构建标准日漫反 Z 字视线动线。
4. **七级镜头景别互斥与同人本三段式闭环**：严禁相邻格同级景别并列。同人感官场景严格落实三大视点闭环：**体位大主格（50%） -> 结合部极近微距 Cut-in（25%） -> 阿黑颜面部破防（25%）**。
5. **日漫视觉特效与拟声词矩阵**：高潮注入集中线 `focus lines`、速度线 `speed lines`、排线 `cross-hatching`、大黑块 `solid black shadows`、网点 `screentone`；纯拟声词调用纯正日文字符（`ドカッ, ズバッ, ゴゴゴ, ドクン, ゾクッ, ヌプッ, ズブッ, クチュクチュ, パンパン, ビクンビクン` 等）。

使用方式：更新两插件并刷新酒馆，开启漫画模式，在 SDT 设置的「前情增强分析」中选择 **漫画 5.0 · 商业大师导演规划**，对正文重新解析分镜后生图。

验证：32 个回归脚本共 708 项检查通过，语法与版本清单一致。

## 1.9.28 / SDT 6.5.18：生成侧对白示例与错误分类

用户提供的模型返回在 5 页、15 格中，把 18 个对白/喊话泡统一放入格级，而所有人物气泡数组为空。只在编译时拦截无法改善模型下次输出。本版调整共享结构化对白指令：先按正文确定说话者及对应人物，再填人物气泡，最后选形状和位置；喊叫、耳语、连续多泡不改变归属。增加完整双人问答 JSON 示范，明确普通可见人物问答时格级气泡为空，双方在各自人物对象中写原句。示例只演示嵌套，不要求复制姓名、剧情、页数或格数。

移除结构化模式中的最终 Text 拼接说明，修正输出核对对页级/格级画外声的混用，补齐工作台最后的人物字段列表中的 bubbles。历史规划原文、旧格式对白与现有编译/记忆逻辑保留。JSON、工具调用、自定义 HTTP 与工作台共用此次提示修正。

字段错误有独立错误码和简短数量/位置摘要，完整问题列表及原始 JSON 在调试详情中保留。界面不再因返回剧情出现“抱歉”、safety 等词把字段错误归为安全拒答；真实服务商拒答按明确错误与响应元数据识别，诊断建议据此分类。使用普通对话与模拟接口验证提示传递和错误处理，真实模型对新指令的遵循率仍待验证。详细记录见 [结构化提示修正](rbq-manga-structured-prompt-2026-10-06.md)。

验证：32 个漫画与 SDT 回归脚本共 707 项检查全部通过；语法、版本清单与差异检查通过。未调用真实解析模型或生图服务。

## 1.9.27 / SDT 6.5.17：结构化气泡归属校验与诊断

用普通办公对话复现：模型把可见人物对白返回到 `page.bubbles` 或 `panel.bubbles` 时，旧程序无警告地编入整页 Text，而对应人物没有台词。此前三个层级的气泡 Schema 共用全部类型，提示中的归属规则没有成为实际约束。

现在页级只允许 `caption/sfx`，人物排除这两类，心声必须归人物。格级保留旁白、拟音、画外声、广播和无尾声源；普通对白、喊话、耳语、颤抖和连泡表示画外声时须明确 `position=offscreen`。新正文解析与工作台新分镜发现明确归属错误时，在记忆/缓存写入和生图前拒绝整次响应，保留返回 JSON 供检查；不会猜说话者或搬移台词，也没有增加自动重试。AI 润色及微调后重绘同样检查新引入的错误，允许原样保留输入草稿已有的错位文字供手动修复。

旧缓存和已有草稿仍可打开、编辑和重绘，文字保持原归属并显示警告。工作台在现有提示栏显示编译诊断，提交时再次提示；SDT 按页查看器展示归属警告。解析失败界面保留错误附带的原始输出，不再误报模型没有返回正文。两种对白方式、旧格式文字恢复与显式空数组清空语义保留。

更新两个插件并刷新后，对普通剧情重新解析分镜再生图；仅重绘旧结果不会自动修复台词归属。PNG 只有最终绘图词，无法恢复原始模型页树或确认解析版本；同名身份与外貌冲突也不能通过猜测自动修正。本版解决明确的字段归属漏洞，不保证模型能正确识别每个说话者或精确画字。实现与验证范围见 [气泡归属检查记录](rbq-manga-bubble-ownership-2026-10-06.md)。

验证：30 个漫画与 SDT 回归脚本共 690 项检查通过，新增 28 项归属与 11 项诊断检查；语法、版本清单与差异检查通过。使用普通剧情与模拟接口，未调用真实模型或生图服务。

## 1.9.26 / SDT 6.5.16：全文选材、分页与分格规划试用

在 SDT 的「前情增强分析」中新增 **漫画 · 全文分页规划（试用）**（`v_manga_narrative`）。先通读当前正文并保留关键行动、完整问答、信息揭示与结果，组织连续内容，再拟定每页起止和任务、逐格画面与文字，参考实际画布容量调整页数、格数和切分，最后输出现有 `segments/page/panels/characters`。页数与格数仍由模型规划，不是本地按字数计算。新版允许均衡分格与连续相同景别，通用文法及文本/工具 Schema 不再强制唯一大主格；实际切分必须写进绘图字段。`reason/intent` 仅用于简短规划说明，不进入生图词。

正文解析、手动描述与测试入口同步传递所选规划、输出合同和画布参考，覆盖 OpenAI 兼容 JSON、主链路工具调用及自定义 HTTP。仍使用一次规划请求，无新增规划重试。正在解析时切换规划只影响下一次请求，已提交响应按自身页格和发起时的绘图快照处理。已有四份历史规划原文及各自的画布传递行为保留；已有选择和旧缓存不自动切换或重排。

使用方式：更新两个插件并刷新酒馆，开启漫画模式，在 SDT「前情增强分析」选择新版，对同一段正文**重新解析再生图**。只重绘旧图不会重新决定页数与分格。比较时保持解析模型、画风、文法、对白方式、画布与生图参数一致，并查看原始响应和各页 `intent`。重点核对关键内容、页面边界、动作阶段、布局与文字容量。

工作台复用新版文法、Schema 与自身画布参考，但继续执行单页任务、自动 1～5 格；容量不足仍返回拆页建议，本版没有多页工作台。角色记忆、完整外貌衣着、灰阶缓存、两种对白方式和绘图参数沿用现有机制。

验证：新增 19 项全文规划回归通过，另有 27 个现有漫画与 SDT 回归脚本全部通过；语法、版本清单与差异检查通过。测试执行生产请求构建、解析、编译及手动生成处理器，接口返回为模拟响应；没有调用真实解析模型或生图接口。工程回归只能证明指令和数据传递，实际选材与出图质量仍需按上述方式对照验证。

## 1.9.25：工作台润色与编辑保留

复现并修复等待 AI 期间手动编辑被旧响应覆盖的问题。单格、批量和整页解析在回填前检查剧情、画面、人物、对白及解析设置；已有改动时保留当前草稿并提示重新解析。单格继续跟随原画格，纯重排仍可接收对应批量结果，等待期间设置的新格位不会被旧位置覆盖。已有 Tag、人物或文字的草稿无需补标题和剧情句子，也可直接润色。

新分镜在显示完整绘图词的同时，私下保存该次出场的完整原色 base/outfit、匹配的灰阶 render 与本格动作。再次润色时将它们分栏输入，结构化文字只放 bubbles，旧格式保留当前唯一 Text 尾部；单格明确输入 currentPanel，其他格仅作连续性参考。模型返回空外貌字段时，按当前格、身份编号和已知姓名复用对应来源，不复制旧动作或旧对白。明确的新外貌、换装及空衣着状态优先，不同来源的服装不能共用旧灰阶视图。缺失灰阶而保留原词的兜底结果不会被保存成有效灰阶视图。复用前先执行共用字段校验，错误类型保持明确诊断，不被转换成有效数据。

这些来源随工作台草稿保存和重载，不写入长期角色档案。手动改视觉词后来源失效，避免下一次润色把旧外貌恢复回来；只改文字和气泡格式仍可复用。旧版已压平且没有来源的草稿不能可靠拆分，继续由同一次解析重建。切换黑白与彩色后须重新 AI 分镜或润色，更新人物、道具、场景和光照，界面会提示；仅换全局画风不会自动重写已有绘图词。

旧整页规划失效时，同时清除 page.base 与 page.non_character 中的过时视觉说明，保留字面文字、已有气泡格式和结构化气泡；有效规划保持不变。页级格数和人数处理也保留重复气泡格式，避免将不同泡的类型及排版合并。

验证：新增 33 项外貌来源、39 项布局失效与文字保留、29 项实际编辑处理器回归，连同既有检查共 **639 项**通过。使用普通成人递信、办公和对话夹具，包含实际 v1.1 文件及宿主代码对照；未调用真实解析模型或生图接口。没有增加模型调用或重试，四份历史前情规划、共享导演指令、SDT、长期角色记忆和上游 Prompt Presets 未修改。以上保证对应数据传递与编辑案例，不代表真实模型的漫画画面质量已经验证。

## 1.9.24：工作台选材与整页规划传递

与实际原预设 v1.1、聊天 SDT 对照，确认此前工作台有三项独立差异：专属指令强制套用铺垫、高潮和收尾特写，默认要求 3～4 格；响应合同只返回 panels，模型额外返回的 page 也被替换成通用 comic；工作台没有实际加入所选的四份前情规划，切换时主要只有 1.8.5 的画布信息不同。普通递信例子证明主格面积、阅读路径、光影及页级旁白会在工作台丢失，原版编译器则会保留。各格 position 与 shot 的旧传递正常。

本版移除工作台额外的强制叙事公式，沿用共享导演的选材、单一定格、人物动作及对白规则。自动规划允许 1～5 格，明确指定格数与经典四格继续优先。整页返回 page.base、可选非人物文字及 panels；主格面积、辅助格排列、阅读路径和光影参与最终生图，而非只在模型解释中出现。page 与完整出场快照一并保存、重载。手动改变格位、增删重排或改变文法、画布等时，旧整页布局失效，页级旁白仍保留；当前能确定的人数由本地出场统计统一组装，避免编辑人物后旧人数与新人数同时发送。

工作台在同一次请求中加入所选的历史前情规划。四份原文保持逐字不变，默认沿用 619 字符版本，只有 717 字符版本接收 mangaCanvas。工作台的最终任务仍限定一页，不返回聊天用的 segments/anchor；没有增加规划调用或模型重试。跨场景或长对白超出单页容量时，模型可返回 capacity_note，显示建议的拆页分界，说明不进入绘图提示词。本版仍不自动生成多页，不能保证任何长度正文都能完整放进单页。

- 固定记忆中的已识别特征优先于 `positive` 中重复的同类外貌，保留动作及末尾 `Text`。相关人物负面词中与补入特征完全相同的排除项会移除。
- `state` 可按实际事件更新 `hair_style`、`hair_length`、`hair_color` 和完整 `outfit`；从该次出场开始顺序延续，可跨页。仅束发/散发不会同时改掉已知发长与发色；只有实际剪发/生长才更新长度。历史开场状态与档案不同时，在首次出场注明。
- 新人物的 `character_memory.initial_outfit` 表示入楼服装，`outfit` 仍表示楼末服装，避免用末格换装结果覆盖前面的格。资料在同一模型响应中提取，全部页格编译成功后才写入长期记忆。
- 黑白转换仍在最终发送时完成，补充支持 `red modified backless cheongsam`、`red high heels` 等带款式修饰的颜色短语，保留服装结构。原始记忆保持原色。
- 已缓存页保存组装后的提示词，重绘不重新读取当前档案；手动编辑和 AI 微调围绕这份快照进行。缺少 `visible` 的旧结构保持原行为，不因升级报错；因此旧图需要重新解析才能获得新机制。

实现边界：当前部位分类覆盖常见英文标签及部分明确的组合短语，不是任意自然语言解析器。1.7.2 起，无法分类的固定身份/自定义外貌标签会保留到有人物部位可见的镜头，避免误删姓名和已有特征；未知衣物部位仍只在完整可见时自动复用。模型仍需正确给出裁切与可见范围。缺少姓名匹配、有效可见部位或模型未给出新人物资料时，不猜档案、不发额外补全请求。此机制提高资料传递的确定性，不能保证模型一定正确判断可见范围或绘图模型完全遵循标签。

范围更正：撤回本轮额外增加的双语去重、动作/手机特例指令，恢复 1.6.4 的相应规则；移除本轮新增的数字年龄、身高标签过滤。保留按可见部位复用角色记忆及其必要配套。

本地验证：59 项漫画回归测试通过，包含漏特征补回、灰阶发送、面部/手部/背部裁切、跨页换装与发型、首次服装状态、关闭记忆、旧页兼容及工作台。前情增强仍为 491 字符，没有新增模型请求或规划重试。Prompt Presets 拼接不变。

## 1.6.2：文字格式与通用动作表达

对照原预设 v1.1.json 的「气泡:边框形状」「文字:演出契约」和「语法:输出协议」，沿用原文字格式：视觉标签、气泡类型、位置和 Layout 写在前面，末尾只用一个 Text:，后面只放实际原句。同人多句用空行分隔，不复制人物槽。示例：

```text
top panel, girl, holding envelope, BubbleType: 通常吹き出し, 右上, Layout: 縦書き
Text: 信收到了。

谢谢。
```

本地文字整理会修复明确的错误结构，例如 `Text: 通常吹き出し, Layout: 縦書き, Text: 信收到了。`，把格式头移到台词前；去除独立整句外包的「」或引号。句内真实引用和普通台词中出现的 Text/Layout 等字样保留。整理作用于页面编译及发送前，因此已缓存的格式错误也可在重绘时修复；缺失的台词不会被程序编造，须重新解析或手动补充。

提示词明确区分可见人物对白、画外声、旁白和拟音。需要上画的文字实际写进 Text，不能只写 speaking/speech bubble；静默格不要求空白气泡。模型对文字归属和漏字的判断仍需实际出图核对。

参考 v23、v24、v40 的通用标签规则，绘图字段要求以英文逗号分隔的标签为主；人物按位置、可见外貌衣着、基础姿势、肢体及接触对象、表情视线组织。自然语言仅用于紧邻标签的短关系补充。新增递信的非露骨动作示例，约束多人物动作归属、可见性、互斥姿势和闭合短词组权重。没有恢复旧预设的固定页数、每页标签配额或额外分析请求。

## 本楼剧情如何变成漫画

SDT 在同一次 Tagger 请求中先规划、后填写绘图词：

1. **承接状态**：历史只提供进入本楼时仍有效的身份、场所、衣着、持物和接触状态。本楼发生的变化按顺序更新，后文的换装不会提前应用到前面的格；角色档案和衣柜不能覆盖已经发生的变化。自动解析只传入目标楼层之前的历史，避免重解析旧楼时混入后续剧情。
2. **选择剧情**：扫描本楼开端到结尾，选择登场、重要动作与结果、关键对白、情绪变化、线索和转场。重复的小动作可以合并；没有新信息的寒暄、纯抽象议论和未发生的假设不需要硬画。没有大动作的告白、拒绝等关键对白仍然可以画。
3. **安排页格**：每个 `segment` 是一张最终图片。先安排画格，再按动作、人数、文字容量和叙事停顿组合成页。普通页 2～5 格仅作容量参考，单格页合法；长对白和复杂互动可跨页。普通插画的“最少分镜数”和 `[图组]` 标记数量不再强制决定漫画页数。
4. **确定每页内容**：每页可用 `intent` 简述主画面、叙事任务和分页理由；各格指定阅读位置、景别、一个相容的定格时刻、可见人物与对白。文法作为演出偏好，不为热血风格强加斜切格，不为四格编造剧情。

### 1.6.1：减轻解析负担

取消 1.6.0 的强制 `story_plan`、逐字 `source`、`beat_ids` 覆盖报告及整次规划修正重试。模型直接提交最终页格，不再因节点引用有标点/措辞差异或排序差异而报“漫画规划校验失败”。收到旧版附带的节点清单时也不以它阻断有效漫画页。

保留前情承接、剧情选择、分页和对白规则，将前情增强缩为简短指令。`intent` 为可选的一句话说明，缺失不报错；可在现有卡片调试详情中查看。页数按实际 `segments` 数量计算。

程序仍检查可渲染的页面结构、人物数据及有效坐标，避免把损坏数据传给绘图模型。引用措辞变化交给现有锚点定位逻辑处理，不触发额外 Tagger 请求。本次移除的是漫画规划重试，接口原有的格式兼容/流式降级逻辑保持不变。

最终选材、对白可读性和画质仍需用实际 Tagger/绘图模型做对照；本次没有测量真实接口延迟。

## 这一版改变了什么

漫画使用“页面 → 画格 → 格内人物”结构。同一格可以有多人，一个人可以跨格多次出场；空镜不创建人物槽。画格数与人物出场槽数分别计算。

聊天自动解析、手动描述生图、工具调用及漫画工作台共用漫画协议。逐人物正负词在最后发送时展平成 NAI `char_captions`，不再通过“一个画格等于一个角色”组织请求。

- 页面及画格的环境、旁白、拟音、画外对白进入全局 caption；可见人物的动作和对白进入本人 caption。
- 各字段的视觉说明排列在 `Text:` 之前，台词和多气泡空行保留，外层对白引号按原预设剥除。台词里的逗号、竖线和 `no text` 不参与标签清理。
- 分页依据事件、文字量和画格容量，允许单格大画面。经典四格保留均等画格，不再与全局“禁止四等分”指令冲突。
- 角色记忆和世界书是导演的资料输入；1.7.0 起，新页按可见部位补入记忆，避免整份全身档案覆盖局部镜头。
- 负面清理以完整标签及闭合权重块为单位。原作排除词由导演根据资料明确填写，不从任意括号猜测作品名。
- 不再强制覆盖请求顶层的绘图模型（保留用户在酒馆/SDT中选定的生图模型）。横向跨页只检测视觉描述，不检测台词。
- **Prompt Presets 插件的画风拼接保持现有行为。**

## 使用

在 SDT 的提示词设置中开启漫画模式，或直接进入独立的“漫画工作台”。关闭漫画模式时会恢复启用前的 SDT 提示词、自定义预设、前情分析及多角色设置。

工作台支持 1～5 格：

1. 输入剧情后使用“AI 智能分镜推演”，或逐格输入剧情后批量解析。
2. 设置各格的位置、大小、景别与环境。
3. 展开“格内人物与文字”，分别编辑每个人的身份编号、姓名、镜头描述、对白及负面词。同一人物跨格使用相同身份编号。
4. 旁白、拟音和画外文字放在单独的非人物文字栏；空镜保留零个人物。
5. 检查组装预览后生成。静默格与有对白的格子使用同一组装流程。

工作台 AI 使用 SDT 的 OpenAI 兼容接口配置。接口未配置、调用失败、JSON 无效或格数不符时保留当前分镜并提示错误，不再用猜测剧情自动替代。经典四格须选择自动或 4 格。

格子的增删、复制或移动会重新安排默认位置，之后可手动调整位置和大小。人物编辑区按需展开，支持手机端纵向编辑。

## 数据协议

每个 SDT `segments[]` 是一个漫画页：

```json
{
  "format": "nai5-comic",
  "label": "Page 1: 放学后",
  "intent": "两人约定同行，以对话为主格、离开后的空教室收尾，同页完成。",
  "anchor": { "text": "她们交谈后转身离开了教室。" },
  "page": { "base": "comic, 2 panels, 2girls, vertical layout" },
  "panels": [
    {
      "id": "P1",
      "description": "top panel, classroom, medium shot",
      "characters": [
        { "character_id": "C1", "name": "甲", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, long hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 一起回家吧。", "negative": "short hair" },
        { "character_id": "C2", "name": "乙", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, short hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 好。", "negative": "long hair" }
      ]
    },
    {
      "id": "P2",
      "description": "bottom panel, empty classroom",
      "non_character": "bottom panel, SFX: 擬音, 吹き出しなし, Text: 咔哒",
      "characters": []
    }
  ]
}
```

默认自动定位。导入的手动定位页可用 `position_mode: "manual"`，每次人物出场需填写有效 `center: {x, y}`（0～1）。编译器检查画格 ID、同格重复人物、正负词字段及手动坐标。

上例是单页结构；SDT 顶层响应为 `{ "shouldDraw": true, "segments": [...] }`，可附简短 `reason`。无需节点清单或原文覆盖报告。文本 JSON 与工具调用使用相同页格结构。

## 已有数据

不会自动删除或改写已保存的分镜、模板或角色档案。旧版工作台混合标签保留为页面内容，不猜测人物身份；点击“AI 润色本格”或批量解析后转换为新结构。新版内置模板已明确拆分人物与环境。

SDT 已缓存的旧分镜继续使用旧数据重绘；重新解析时要求新协议。漫画页换装通过 AI 微调按人物出场更新，避免字符串拼接同时保留新旧衣服。
