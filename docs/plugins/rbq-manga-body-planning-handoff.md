## 1. 用户目标与术语

用户明确提出：

> 正确分析出这段正文应该画什么内容，画几页，每一页漫画应该画什么，画几格，格子怎么切分，每格画什么。

本任务中的“SDT LLM 正文生成”，按当前对话和代码语境，指 **SDT 将已经生成的聊天正文交给 LLM，生成漫画页格规划与绘图描述**。不修改酒馆负责续写故事的主模型，不让漫画解析器续写、重写或补全原剧情。

目标链路：

```text
当前楼层完整正文 + 必要前情/角色资料 + 当前绘图条件
  → 选择值得呈现的内容
  → 理清事件、问答、反应和状态变化
  → 拟定各页内容与边界
  → 确定各页画格内容、文字与空间需求
  → 复核容量，调整页数/格数/版式
  → 输出最终 page / panels / characters
  → 现有解析、角色快照、编译、生图链路
```

完成标准不是提示词更长、画格更多或版式更花，而是读者能通过漫画读懂原文中的关键行动、信息变化及其结果。

## 5. 全文规划算法：模型应如何做决策

以下是同一次请求内的工作顺序，不要求输出长篇思维过程，不要求程序实现一个基于字数的机械导演。

### 5.1 确定素材边界和进入状态

1. 从当前正文开头读到结尾，不能只取最后一段。
2. 历史消息、角色卡、世界书、记忆只提供身份与连续性参考，不自动成为本次新页面。
3. 识别当前场景、时间、可见人物、已有持物、服装和关系状态。
4. 区分真实发生、原文明确回忆、假设、比喻和心理表达；不得将未发生的设想画成现实行动。
5. 明确回忆若为正文必要内容，可以表现，但需与当前时间线区分；普通引用历史不自动重画。

### 5.2 选择画面内容

优先保留：

- 改变后续剧情的行动及结果。
- 必要的提问、回答、条件、理由、决定、拒绝、承诺。
- 信息揭示、关键物件或线索、情绪转变及其直接反应。
- 理解空间和因果所必需的场景交代与转场。

可合并或省略：

- 同一状态的重复修饰和同义心理描写。
- 不产生新信息的重复对白。
- 可由同一画面呈现的外貌、环境与静态细节。
- 对本段理解无贡献的抽象议论或纯修辞。

“完整转译”指关键意义与因果完整，不要求每一句叙述都变成画格。反过来，不能把长对白中的条件和理由当作冗余而删掉。

### 5.3 划分叙事段落

将选中的内容理解为连续变化，例如“进入房间 → 发现缺失物件 → 询问 → 获得线索 → 决定离开”。

- 一个叙事段可以包含多格，也可以跨页。
- 多个紧密相连的短段落可以合在一页。
- 句号、自然段、原有图组标记都不直接等于页边界。
- 不强行把正文改成起承转合，不创造原文没有的反转或高潮。

### 5.4 拟定页面任务与边界

每页要能简短说明：

1. 从哪个事件/状态开始。
2. 到哪个事件/状态结束。
3. 必须呈现什么关键内容。
4. 是否有需要强调或停顿的时刻。
5. 下一页如何从当前结果接续。

分页候选点：场景或时间变化、阶段性结果、长问答的自然停顿、关键揭示前后、容量不足处。它们是候选点而非强制规则。

不应仅为“翻页悬念”拆散本来短而完整的问答，也不应为了同场景就把过长互动挤在一页。

### 5.5 决定每格画什么

每格至少确定：

- 内容职责：交代、行动、信息、回应、反应、结果、停顿或过渡。
- 可画时刻：当前动作处于何阶段，哪些结果尚未发生。
- 可见人物与道具：谁在场、谁持物、谁对谁做什么。
- 画面焦点：读者需要看清的具体内容。
- 文字：谁说什么，哪些为心声、旁白、画外声或拟音。
- 镜头：用何种景别、角度和裁切让内容清楚。

同格允许短对白与持续姿态，不把“一格一个时刻”机械解释成只能容纳一个字或单一动作词。不能同格同时要求互斥的动作阶段，例如“递出信 → 接过 → 放进口袋”。

允许同景别连续出现；只有需要的观察内容发生变化时才换机位，不为景别多样而随机切镜。沉默或空镜应有停顿、空间或情绪用途，不能成为凑格工具。

### 5.6 估计容量，反向调整页数与格数

综合考虑：

- 实际画布宽高与方向。
- 需要辨认的人物数量和互动复杂度。
- 每格必要的对白及气泡位置。
- 需要看清的表情、道具和环境。
- 大幅展示、快速推进或停顿的叙事需要。

若拥挤，先检查是否存在无意义重复，再调整格形/面积，最后在合理边界拆页。不能优先删掉关键对白或把互斥动作塞进同格。

若页面空洞，检查相邻页是否可合并；不能为了消耗页数添加剧情。

不采用“每 N 字一页”“每个事件一格”“统一每页 3～5 格”的硬算法。允许单格页、均衡对话页和内容充分的较多格页；具体能力需要真实画布与绘图模型验证。

### 5.7 决定怎么切格

先确定每格内容及空间需求，再选布局：

- 横向互动、多人关系需要足够横向空间。
- 竖向主体、纵深站位可采用纵长格。
- 简短细节、物件、反应可以用小格，但不是所有反应都应缩小。
- 长对白须给气泡与主体留空间。
- 有突出时刻时扩大相应格；无突出时刻可均衡排列。
- 斜切、插入、破框等仅在适合内容且阅读顺序清楚时使用。

必须描述实际结构，如“上排右窄左宽两格，中排通栏一格，下排右左两格”，而非只罗列 `asymmetric layout`、`cinematic composition`。

对复杂跨行布局，逐格阅读顺序必须唯一、邻接关系可理解，不能只写“反 Z”。格内位置词、人物位置前缀和页级总布局必须相符。

### 5.8 提交前复核

模型完成一次简短内部检查：

- 开头和结尾关键内容是否存在？
- 重要问答、条件、理由与结果是否遗漏或错序？
- 是否从历史中取出了额外剧情？
- 同格是否包含互斥阶段？
- 跨格跨页人物、持物、衣着和场景是否连续？
- 页数是否来自内容与容量，是否过度压缩或无意义扩写？
- 页级布局、实际格数、格位及文字空间是否相容？

这是提示词内的核对，不恢复强制 `story_plan` / `beat_ids` 清单，也不因文学措辞不一致触发自动重试。

## 6. 推荐架构：新增策略，复用现有页格协议

## 7. 输出合同与可观察性

### 7.1 保持主协议

```text
shouldDraw
reason                         简短选材与实际分页结论
segments[]                     每项一页/一张图片
  format = nai5-comic
  label
  anchor.text                  当前正文逐字片段，用于卡片定位
  intent                       本页内容范围和叙事任务
  page.base                    实际页形、格数、布局、阅读路径、光影
  panels[]                     按阅读顺序
    id
    description                格位/大小/景别/环境
    non_character / bubbles    遵循选定文字协议
    characters[]               本格实际出场人物
```

不另建一套与 `segments` 重复的页树。实际页数以 `segments.length` 为准，实际格数以对应 `panels.length` 为准。

### 7.2 最小诊断信息

- 复用 `reason`：概述选了哪些内容、为何形成这些页。
- 复用 `intent`：一两句说明本页起止、重点与必要拆页理由。
- 如现有格内字段不足以审阅选材，可新增**可选** `panels[].summary`，只写“本格画什么”，不要求逐句引用原文或输出推理过程。
- 新可选元数据缺失时不使旧响应失败；只保存和展示，不进入绘图 caption。
- 若新增字段，必须覆盖 schema、标准化、快照保存、重载、调试详情及工作台转换；无法完整贯通时先使用现有字段，不做半套实现。

即使没有额外元数据，真正的动作、格位、镜头与文字仍必须出现在现有绘图字段中，不能只在 `intent` 写“主格扩大”，实际 `page.base` 却不变。

### 7.3 输出边界

- 没有值得呈现的内容时沿用 `shouldDraw=false` 合同，不能为了漫画模式强制生成页。
- 不按关键内容节点数量强制创建相同数量的 segment。
- 锚点用于定位，不用于证明全部内容覆盖，不把锚点字符串匹配当作叙事质量校验。
- 明确用户格数/页数要求与经典四格具有相应约束；无法容纳时说明限制，不静默丢内容。不要为本次顺便新增复杂预算 UI。
- 模型输出截断或缺页不能伪装成完整成功。沿用结构解析失败处理，保留诊断；不自动编造缺失部分。

## 8. 新规划提示词起草基线

以下是可落地的规划模块草案，实施时结合共享系统去重、消除冲突，不必逐字照搬：

```text
【正文改编为漫画：全文规划】
本次将 currentMessage 的已定稿正文改编为漫画页。先通读全文，选定应呈现的内容，再安排页、格与版式，最后填写绘图字段。历史和角色资料仅用于身份及状态承接，不重画历史，不续写剧情。

先识别正文中的实际事件、关键问答、信息揭示、情绪变化及结果。保留理解剧情必需的行动、条件、理由、回应与转场；合并重复修饰、同义描写和无新信息的重复镜头。不按句号、段落或图组标记划页，不把假设、比喻画成已发生事件。

将相关内容组织成连续叙事段，拟定各页起点、终点和任务。一个事件可跨格跨页，相邻事件也可同页。每页不必有高潮、大主格或悬念。页数应来自内容、演出需要及实际画布容量，而非预先凑数。

逐格选择一个可表现的相容时刻，确定可见人物、动作对象、持物、姿态、反应与本格文字。让读者能理解各格之间的因果、回应或时间推进。不要同时画准备、完成和完成后的互斥姿势。短问答可以同格，重要动作也可分格；避免无依据地补对白、反应或细节。

先明确每格需要看清什么，再决定景别和面积。连续镜头可保持同景别，平稳对话可均衡分格，重要时刻可扩大。格数由必要画面与可读空间决定，不统一套三格、四格或固定主辅结构。

同时为对白安排空间。拥挤时合并重复内容、调整格形或在自然边界拆页，不能截去关键台词的条件、理由、句尾或最后事件。空洞页面可与相邻页合并，不新增剧情填空。

确定最终布局后，在 page.base 写实际格数、各区域大小和邻接排列、阅读路径；各格与人物使用一致格位。按所选阅读方向排列 panels，明确插入格属于独立画格还是同格细节，不重复计数。所有构图与动作决定都落实到实际绘图字段。

提交前核对正文首尾、关键内容、问答顺序、状态连续性、容量、实际页格数与布局一致性。一次返回最终页格 JSON。reason/intent 只写简短内容与分页结论，不输出额外节点清单或长篇推理。
```

该模块不替代人物记忆、文字协议或灰阶模块。不要同时保留一份旧规划全文再叠加一份新规划全文。

## 9. SDT 入口实施检查单

### 9.1 主正文请求

1. `buildRequestPayload` 的漫画分支保留完整当前正文和前情隔离。
2. 新策略传入实际画布信息，明确其属于规划参考，不修改生图尺寸。
3. `segmentInstruction`、英文摘要与新规划一致，避免“一节点一图片”的普通插画语义混入。
4. OpenAI 兼容路径的 system 合并、文本 JSON schema 与工具 schema 同步。
5. 自定义 HTTP 的 `mangaInstruction`、`outputSchema` 和画布字段同步；不能依赖自定义服务读取本地 system message。
6. 角色卡、记忆、衣柜、世界书仍按现有开关传递，不扩大资料来源。
7. 一次响应中的多页全部走现有标准化、外貌解析及锚点卡片流程。

### 9.2 其他入口

搜索所有 `planningPrompt`、`planningContext`、`getRequestEnhancedContext`、`v_manga_185`、`mangaInstruction`、`segmentSchema` 调用点。

重点检查：

- 手动描述入口 `parseTaggerSegment` 中仅为 717 字版本增加画布的条件。
- 测试请求或内嵌生成入口是否独立拼装 payload。
- 已有单页 AI 微调继续使用“当前页编辑”合同。
- 缓存重绘不重新执行规划；只有重新解析正文才得到新页格结构。
- 两种文字模式和两类接口使用相同的剧情与分页语义。

### 9.3 不得顺带破坏

- 完整角色 `base/outfit`、姓名映射、跨页持物/衣着变化和已有长期记忆行为。
- 黑白 `render` 视图与原色档案隔离、缓存复用。
- 结构化 `bubbles` 与 legacy `Text:` 两种对白方式。
- 人物对白归本人，旁白/拟音/真正画外声归页或格。
- 普通插画模式、模型选择、采样器、步数、CFG、画布和用户画风。
- 请求取消、聊天切换、正文编辑、插件卸载及晚到响应保护。
- 手动定位坐标合同；禁止把某个格内坐标当成整页坐标。
- 历史缓存与旧页树，不自动迁移重排或偷偷重新出图。

## 10. 分页与分格示例：用于理解，不用于固定答案

### 10.1 输入正文

> 林遥走到车站长椅旁，看见周宁还在等她。她攥着信封停了片刻，才把信递过去：“灯塔那边的回信。”周宁接过，拆开信封读完，说：“他们同意了，但我们必须今晚到。”林遥看了看站钟：“末班车还有十分钟。”周宁把信折好放进口袋，拿起长椅上的包：“那就走吧。”两人朝站台入口跑去。

### 10.2 必须保留的意义

- 会合与信件交接。
- 回信同意，但要求今晚到达。
- 末班车只剩十分钟。
- 收信、拿包、决定出发及跑向入口的结果。

迟疑可以展开，也可以在递信画面中表达；不要求一定单独一格。不得删除“今晚到”或“十分钟”，否则行动理由不完整。

### 10.3 一种两页方案

| 页 | 页面任务 | 可采用的分格内容 | 可采用的切分 |
| --- | --- | --- | --- |
| 1 | 会合、交信、获知今晚必须到 | ①长椅边会合；②交接信封；③周宁读后告知期限 | 上排右左两格，下排较高通栏格，为回答留空间 |
| 2 | 时间紧迫，立即出发 | ①林遥看站钟并说十分钟；②周宁将信收入袋中；③拿起包并说走吧；④两人跑向入口 | 上排右左两格，中排通栏，下排较宽行动格 |

格 2、格 3 是否需要分开，应取决于具体定格与容量；不能在同格同时要求同一只手收信、拿包、拉人。若采用兼容姿态合并，需写清当时状态。

这不是唯一答案。一个清楚的较多格单页、三页慢节奏版本也可能成立，需结合画布与文字实际判断。评测不应断言此正文“必须两页七格”。

### 10.4 典型错误

- 只画最后奔跑，忽略信件内容与赶车理由。
- 每句话生成一页，造成大量重复镜头。
- 第一页大量特写，最后一页挤入读信、看钟、收信、拿包、奔跑。
- 虽有“递信、读信、收信”三个词，实际都写在同一格同一人物描述里。
- `intent` 说两排分格，实际 `page.base` 只有 `vertical layout`。
- 页面总述上排右左、格内位置却左上右下，阅读路径自相矛盾。

## 11. 测试与质量评估

严格区分三层结果，不能用离线断言数量代替实际漫画质量。

### 11.1 工程回归

新增测试应执行生产函数和实际请求构建，验证真实行为，不仅搜索提示词关键词。

至少覆盖：

1. 新策略识别、选择、保存、重载、切回历史版本与关闭漫画恢复。
2. 历史四份文本 hash 不变，旧画布注入条件不变，新策略获得真实画布。
3. 同一普通正文经过 JSON、工具调用、自定义 HTTP 时具有一致规划合同。
4. 普通 `minSegments` 和图组数量不强迫漫画页数。
5. 当前正文完整、历史范围正确、不包含未来楼层。
6. 模拟响应包含多页、多格、空镜、多人物与文字，解析后完整保存且编译传递。
7. 新可选元数据缺失时旧数据可用；存在时不进入绘图 caption。
8. 已有页编辑与缓存重绘不意外触发全文重规划。
9. 进行中切换策略或正文变化时不混用请求合同；晚到结果不污染新状态。
10. 单格页、均衡分格、相同景别连续出现不被程序强制改写。

以上命令是实施后的建议验证项，**本交接文档没有声称已经执行或通过它们**。

### 11.2 真实 LLM 规划评估

建立普通、非露骨文本样本，覆盖：

| 样本 | 检查目标 |
| --- | --- |
| 短对话，无重大转折 | 不强造高潮或固定大格 |
| 递物、接收、阅读、收起 | 事件阶段与持物连续 |
| 带条件和理由的长问答 | 容量不足时合理扩展，不截断关键意思 |
| 多场景与时间跳转 | 页面边界、转场清楚 |
| 一个瞬间有大量修饰 | 不按字数过度分页 |
| 短正文包含多个真实变化 | 不因字数少漏画结果 |
| 三人轮流发言 | 出场和对白归属正确 |
| 心理描写、假设与比喻 | 不把未发生事件画成现实 |
| 正文结尾有决定性结果 | 不因前段花费过多而遗漏结尾 |
| 前情中有鲜明事件、当前正文平静 | 不从历史盗取“精彩画面” |

对比建议：同一解析模型、同一正文、同一资料、同一画风/文法/对白方式/画布，旧默认规划与新版各重复两三次；记录实际请求、原始响应、解析页树、最终绘图词。新旧策略的差异必须可解释，不能同时换模型和画风后归因于规划器。

每份结果人工检查并记录：

- 关键内容是否遗漏或被改写。
- 页边界是否自然，是否过度压缩或拉长。
- 每格画面是否可执行，是否存在互斥动作。
- 布局是否明确且前后一致。
- 对白是否完整、顺序与归属是否正确。
- 跨页状态是否连续。

不要将“命中固定页数/固定格数”作为通用分数。测试样本可以定义必需事实，但允许多个合理分镜方案。

没有真实接口、调用失败或未进行实测时，明确报告“工程验证完成，模型规划质量未验证”，不能用手写夹具充当 LLM 输出。

### 11.3 真实图片检查

在规划结果合格后选代表样本出图，检查格数、切分、人物动作、文字与可读性。分别记录：

- **规划错误**：原始页格计划已漏剧情或动作矛盾。
- **编译错误**：计划正确，最终提示词丢字段或串归属。
- **生成偏差**：最终提示词正确，绘图模型没有执行。

只有最后一类才考虑渲染约束或其他生成方案。本任务不默认引入逐格生成拼页、图像区域控制或后期排字重构。

## 12. 工作台第二阶段

SDT 主链路完成后再实施：

1. 新建全文漫画任务复用同一规划策略，不另写一套相互矛盾的导演规则。
2. 单页编辑和多页新建区分：单格润色不新增页，单页修改不自动重排全部页。
3. 多页草稿保存每页 page、panels、文字和人物快照；切换页时不能丢弃编辑。
4. 旧单页草稿兼容加载为一页，不擅自重解析。
5. 页内编辑使对应页的旧布局失效；不错误清空其他页布局或页级旁白。
6. 取消、重排、删除页/格、切页和晚到响应沿用已有保护原则。
7. 多页发送保持正文规划顺序、各页独立人物出场和对白归属。

具体存储迁移与 UI 方案留到 P2 基于已稳定的 SDT 输出设计，不能为预想工作台结构倒逼 P0 重写全部协议。
