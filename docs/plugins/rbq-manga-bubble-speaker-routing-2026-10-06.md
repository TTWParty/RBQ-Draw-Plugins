# 结构化气泡的明确说话者引用与归位

日期：2026-10-06。本地版本：漫画 **1.9.30**、SDT **6.5.20**。

## 问题与证据

本次返回有 4 页、13 格，多数人物文字已嵌套在对应人物中，仍有一处 `P2_2.bubbles` 普通对白处于格级，且没有说话者引用。只增加嵌套示例和拒绝校验无法处理模型偶发的层级误放。只有一位可见人物也不能证明每一句均由其说出；可能存在画外声。

本次只分析字段结构，开发与测试采用普通办公、递信和对话数据，不复用附件剧情进行生成或润色。

## 输出与处理契约

`speaker_id` 是可选字符串，值必须逐字等于已声明的 `character_id`，不接受姓名、数组索引、空字符串或未知编号。已知编号从本次全部页树及编辑输入页树收集，不会添加人物来满足引用。共享结构化提示、文本输出示例与工具 Schema 均包含该字段；旧格式 Text 分支和没有编号的正确历史响应仍兼容。

优先输出在正确人物下：

```json
{
  "character_id": "C2",
  "bubbles": [
    {
      "type": "speech",
      "position": "left-lower",
      "layout": "vertical",
      "speaker_id": "C2",
      "text": "资料收到了。"
    }
  ]
}
```

若同一个气泡误放到本格 `panel.bubbles`，满足下面全部条件时会归回人物：

1. 有明确 `speaker_id`，并在同格唯一对应一位人物。
2. 类型可归人物，不是 `caption/sfx`；未明示 `offscreen` 类型或位置。
3. 目标人物没有非空结构化文字、旧格式 `Text:` 或无效气泡字段。

保持原来的文字、类型、位置、排版和编号。多个气泡按源数组先后加入各自人物，不去重、不改句、不推断与已有人物文字的先后。每次归回只记录位置与编号，不把文字塞入诊断。编号只用于程序归属处理，不进入 NAI 绘图字幕。

| 返回情况 | 处理 |
| --- | --- |
| 正确人物层级，无编号 | 兼容原行为 |
| 格级人物文字有同格唯一编号，目标无文字 | 归回对应人物 |
| 格级人物文字没有编号 | 不猜测，继续归属校验 |
| 明示画外类型或位置 | 保留格级；已知编号可在其他页或编辑输入中声明 |
| 未知/空/无效编号、同格重复身份 | 拒绝引用，保留原响应 |
| 人物气泡编号与外层人物不一致 | 拒绝，不迁往另一个人物 |
| `caption/sfx` 填了人物编号 | 拒绝，不把非人物文字归人物 |
| 目标已有结构化或旧格式文字 | 拒绝，需明确合并后的顺序 |
| 页级人物文字，即使有编号 | 不归位，继续拒绝错误层级 |

## 接口和入口

公开接口 `RBQ.api.mangaProtocol.normalizeResponseBubbles(pages, previousPages = [])` 返回深复制后的页数组。先检查所有引用和目标，再统一搬运；原输入不修改。`recoverResponseText` 在旧格式兼容恢复之前调用它，再做归属检查。

SDT 正文解析、JSON/工具调用/自定义 HTTP 与工作台新分镜经共享恢复入口处理。工作台润色和 SDT 单图微调先归位，再按输入基线校验，随后解析外貌和编译；编辑不会重新启用旧格式恢复，明确 `[]` 清空仍生效。单独的编译器不搬运历史缓存或草稿，也不重新识别说话者。

格级原本的非空结构化气泡已覆盖旧 `non_character Text:`。搬走最后一泡时，程序清理被覆盖的旧文字镜像，保留视觉说明，避免空数组被旧格式恢复流程重新激活后重复画字；包括编译器兼容的字符串数组形式。

成功说明经 `_mangaTextWarnings` 展示在 SDT 诊断；工作台把这些说明与现有容量说明合并后显示在预览提示区。引用失败使用 `MANGA_BUBBLE_SPEAKER`，归属失败仍使用 `MANGA_BUBBLE_OWNERSHIP`；两者都归为气泡诊断。完整问题和搬运前的原始 JSON 留在调试数据中。

## 验证与边界

回归覆盖明确引用归位、画外声、重复编号、未知编号、字符内编号不符、目标文字冲突、原顺序和重复发言、字符串/数组旧镜像、缓存编译兼容、NAI 最终字幕、SDT 多接口与润色、工作台新分镜/编辑/明确清空、成功说明以及失败前不写记忆和缓存。

最终 **33 个漫画与 SDT 回归脚本、746 项检查全部通过**。新增独立说话者归位套件 31 项；SDT 诊断套件 19 项、错误分类套件 9 项。生产文件与修改测试语法、插件版本及缓存 URL 清单、差异检查通过。

使用普通模拟接口响应，未调用真实解析模型或生图服务。该处理验证的是模型**声明**的引用；模型若把正文中的说话者认错，程序仍无法仅凭 ID 证明语义归属。文字和气泡的精确出图位置仍由绘图模型决定。

使用方式：更新漫画与 SDT 两个插件并刷新酒馆，再重新解析正文。旧 JSON 不会自动补出 `speaker_id`；只重绘旧图不会触发这次归位逻辑。
