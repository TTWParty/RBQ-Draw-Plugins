# 漫画模式与漫画工作台

插件 ID：`rbq-manga-mode`。入口：[manga-mode.js](../../plugins/manga-mode.js)。

版本：**1.7.0**，配套智能生图（SDT）**6.3.0**。更新时请确认两个插件均为上述版本或更高，并刷新酒馆。

## 1.7.0 / SDT 6.3.0：按可见部位落实角色记忆

开启角色记忆后，新解析的漫画人物通过 `name` 关联档案，填写简短的 `visible` 部位数组。程序从已存外貌、服装中选取适用标签，与本格动作和对白组合；不再完全依赖模型逐格重写已存资料。工作台 AI 分镜采用相同组装逻辑，但不写回聊天档案。

- 部位为 `hair / face / eyes / torso / hands / legs / feet`。例如面部特写选择前三项，手部特写选择 `hands`，背面不选 `face/eyes`。模型负责判断裁切和遮挡；程序不会根据一个模糊镜头名猜可见范围。
- 固定记忆中的已识别特征优先于 `positive` 中重复的同类外貌，保留动作及末尾 `Text`。相关人物负面词中与补入特征完全相同的排除项会移除。
- `state` 可按实际事件更新 `hair_style`、`hair_length`、`hair_color` 和完整 `outfit`；从该次出场开始顺序延续，可跨页。仅束发/散发不会同时改掉已知发长与发色；只有实际剪发/生长才更新长度。历史开场状态与档案不同时，在首次出场注明。
- 新人物的 `character_memory.initial_outfit` 表示入楼服装，`outfit` 仍表示楼末服装，避免用末格换装结果覆盖前面的格。资料在同一模型响应中提取，全部页格编译成功后才写入长期记忆。
- 黑白转换仍在最终发送时完成，补充支持 `red modified backless cheongsam`、`red high heels` 等带款式修饰的颜色短语，保留服装结构。原始记忆保持原色。
- 已缓存页保存组装后的提示词，重绘不重新读取当前档案；手动编辑和 AI 微调围绕这份快照进行。缺少 `visible` 的旧结构保持原行为，不因升级报错；因此旧图需要重新解析才能获得新机制。

实现边界：当前部位分类覆盖常见英文标签及部分明确的组合短语，不是任意自然语言解析器。无法分类的自定义特征只在完整可见时自动复用；局部镜头可在 `positive` 明确补充。缺少姓名匹配、有效可见部位或模型未给出新人物资料时，不猜档案、不发额外补全请求。此机制提高资料传递的确定性，不能保证模型一定正确判断可见范围或绘图模型完全遵循标签。

同轮收紧语言与动作指令：简体中文模式从外语及中文译文中只取一份中文；单格只描述一个时刻，不用 `then` 混写准备/执行/完成，保持道具实体和持有手明确。这两项属于模型指令，尚未通过真实出图证明文字和道具错误消失。

本地验证：59 项漫画回归测试通过，包含漏特征补回、灰阶发送、面部/手部/背部裁切、跨页换装与发型、首次服装状态、关闭记忆、旧页兼容及工作台。前情增强仍为 491 字符，没有新增模型请求或规划重试。Prompt Presets 拼接不变。

## 1.6.4 / SDT 6.2.8：对照原预设的适配

对照下载目录的 `v1.1.json`，补回原版关于发型结构、跨页道具与场景连续性、全页逐人物负面词、气泡阅读位置和持续光源的要求。具体对应关系见 [原预设适配对照](rbq-manga-v1.1-comparison.md)。

- **选材与分页**：按本楼事件、对白容量分配页面；数组顺序对应阅读顺序，主格不必是首格；容量不足先压缩重复视觉内容、再分格分页，不截掉关键对白或结尾。
- **人物与记忆**：移除漫画建档指令中“无资料可以自行设定外貌”的冲突句；临时束发、湿发随镜头变化，固定外貌不因此重写；保留已知国籍、族裔等原有七维要求。
- **动作与连续性**：补回道具结构、开合破损、固定地标、门窗方向与变化生效时间；人物出场保留镜头可见的完整发型特征；负面词检查本页其他格的人物，排除自身与共享特征。
- **文字与色彩**：先发言的气泡居右上，尾巴随本格说话者位置；同人连续气泡成组，外语及道具文字横排。黑白指令覆盖道具和环境，长期记忆保留原色；彩色模式保持连续场景光照。回忆格的黑底是格外排版，不自动改变场景照明。
- **分镜文法**：移除插件额外写入的近景 `looking at viewer` 示例及“第三格突发转折、第四格搞笑落点”等扩写；保留原版四格起承转结与喜剧模式的风格要求，动作效果仍依据剧情。工作台不再统一附加动态角度、速度线、恋爱气氛或夸张表情；这些由实际分镜决定。
- **运行逻辑**：工作台按人物 ID 汇总所有出场中的明确主体标签，避免末格手部特写覆盖已有身份，或把 `looking at girl` 当成女性主体。身份不明或相互冲突时不猜人数类别。工具 schema 补齐编译器已有的可选手动坐标协议，默认仍自动定位。

前情增强保持 **491 字符**；默认黑白/通用文法系统指令从 4278 增至 4995 字符，增加的是缺失规则。没有增加模型请求、规划报告或校验重试；不承诺真实接口延迟不变。Prompt Presets 拼接保持现状。

验证：52 项漫画回归测试通过；情境系统 17 个场景、289 项断言与 15 项静态检查通过，并完成两个插件的 JavaScript 语法检查。这里验证结构、请求和记忆链路，没有用真实模型进行画质、文字准确率或耗时评测。旧缓存要重新解析才会应用新的导演指令，单纯重绘不会重新分配对白与镜头。

## 1.6.3 / SDT 6.2.7：链路检查与修复

- **人物颜色与黑白模式**：最终请求中的人物提示词，对明确的颜色＋头发/眼睛/衣物短语做灰阶转换，例如 `deep purple qipao` → `dark grey qipao`。支持闭合的数字权重与花括号权重；不改对白、持久角色记忆、画师/带作品括号的姓名标签，也不改彩色或自定义画风。Prompt Presets 的画风拼接保持不变。转换只覆盖明确的短语，不保证任意自然语言或其他来源的颜色指令都被消除。
- **边框排版**：当前选定的出血/白边/黑线标签直接进入最终请求，避免完全依赖 Tagger 转述；天地出血移除了自身附带的 `white border` 矛盾词。重复经过插件钩子时不重复添加相同标签。
- **首次资料与工作台**：只有已存非空外貌才跳过首次角色卡读取，仅有服装或空白外貌的档案仍可获得角色卡。测试生图入口补齐角色卡资料；漫画工作台的 AI 分镜读取开关允许的角色卡和当前聊天记忆，参考资料不另发模型请求，也不从工作台的画格输出反写记忆。
- **画廊重绘**：保留漫画标记、格内人物和手动坐标；整页正向不再重复包含扁平化人物词。空镜重绘会清除旧人物。已存漫画页在关闭全局漫画开关后重绘仍使用 V5 漫画处理，但沿用当前漫画样式配置，并非保存一份历史样式快照。
- **坐标与接口**：修复手动编辑时坐标 `0` 被当成 `0.5`；工作台接口同时接受 Base URL 和完整 `/chat/completions` 地址，避免重复拼接。工作台 AI 分镜目前仍使用 OpenAI 兼容接口配置。
- **对白与配角**：补充可见回答者、匿名配角、背影的人物槽要求，以及问答先后、画外回答归属本格的指令。没有根据台词猜人物或增加自动重试；模型是否执行正确仍需真实输出验证。

本次本地验证覆盖 50 项漫画回归用例，包括结构编译、两种钩子顺序、记忆开关、请求格式、重绘、坐标、文字保留和工作台接口。测试使用模拟接口，不代表已验证真实生成质量或延迟。已有非空但不完整的外貌仍需主动重新提取；之前已缓存的错误台词归属需重新解析或手动修正，单纯重绘不会自动知道谁说了哪句话。

## 1.6.2：文字格式与通用动作表达

对照原预设 v1.1.json 的「气泡:边框形状」「文字:演出契约」和「语法:输出协议」，沿用原文字格式：视觉标签、气泡类型、位置和 Layout 写在前面，末尾只用一个 Text:，后面只放实际原句。同人多句用空行分隔，不复制人物槽。示例：

```text
top panel, girl, holding envelope, BubbleType: 通常吹き出し, 右上, Layout: 縦書き
Text: 信收到了。

谢谢。
```

本地文字整理会修复明确的错误结构，例如 `Text: 通常吹き出し, Layout: 縦書き, Text: 信收到了。`，把格式头移到台词前；去除独立整句外包的「」或引号。句内真实引用和普通台词中出现的 Text/Layout 等字样保留。整理作用于页面编译及发送前，因此已缓存的格式错误也可在重绘时修复；缺失的台词不会被程序编造，须重新解析或手动补充。

提示词明确区分可见人物对白、画外声、旁白和拟音。需要上画的文字实际写进 Text，不能只写 speaking/speech bubble；静默格不要求空白气泡。模型对文字归属和漏字的判断仍需实际出图核对。

参考 v23、v24、v40 的通用标签规则，绘图字段要求以英文逗号分隔的标签为主；人物按位置、可见外貌衣着、基础姿势、肢体及接触对象、表情视线组织。自然语言仅用于紧邻标签的短关系补充。新增递信的非露骨动作示例，约束多人物动作归属、可见性、互斥姿势和闭合短词组权重。没有恢复旧预设的固定页数、每页标签配额或额外分析请求。

## 角色外貌记忆

### SDT 6.2.6：接通漫画角色卡参考指令

开启「参考角色卡信息（未建档时）」后，漫画请求也带专门的角色卡参考指令，读取 `characterCardInfo` / `characterCardInfo_base64` 的描述及世界书，明确已知身份外貌优先于模型猜测、未知不猜、已有不漏。可见特征用于格内人物 `positive`；只有开启记忆且输出协议要求时才写 `character_memory`，不回退到旧版分镜字段。普通兼容接口与自定义 HTTP 都携带该指令，关闭记忆仍能参考角色卡绘图。手动输入入口同时传入描述与历史供角色卡世界书关键词匹配。

两种模式共用原有首次角色卡收集逻辑；本次补充漫画字段适配，不改变已有档案跳过收集的条件，不增加模型请求或重试。

### SDT 6.2.5：取消角色卡注入截断

自动注入角色卡不再截断描述到前 1200 字符；角色卡内世界书不再截断每条到前 600 字符，也不再只取前 8 条。仍需开启角色卡注入，世界书仍按启用状态与上下文关键词筛选。已有角色档案仍沿用原来的跳过角色卡注入逻辑；需要更新旧档案时使用「从角色卡提取 / 更新外貌」。本次仅移除上述内容与条数限制，没有增加请求次数；实际请求长度与耗时取决于资料量。

### SDT 6.2.4：移除人物示例，补回国籍与族裔维度

实际反馈中的外貌记忆与 6.2.3 的完整人物示例逐字相同。移除该示例，仅保留提取维度、字段分工和格式规则，避免将示例外貌当作角色默认值。已有记忆不自动删除或改写，应对照角色原设手动修正或主动重新提取；这项改动不保证修复对白归属或黑白画面中的彩色提示词。

对照用户提供的旧版提示词，恢复第二维中被缩掉的族裔、国籍/地域背景，并与面相分别检查。漫画建档、角色卡提取及输出字段说明均明确要求保留已知身份特征；未知不猜，不根据姓名或动漫画风自动认定国籍。其余维度同样要求保留有依据的特征，不能以避免臆造为由省略已有设定。

### SDT 6.2.3：补齐标签规格与重新提取

漫画自动建档和角色卡导入共用英文逗号标签规格：按主体类别、面部、年龄阶段、头发、眼睛、体型、肤色与永久标记七个方面检查已知外貌；服装按颜色、已知材质、款式、长度/状态及细节逐件组织。人物记忆不带 `1girl` 等人数，不机械抄录精确年龄/身高，优先表达对应的可见特征，也不为凑齐维度编造未知族裔或外貌。黑白画面仍保留原始颜色资料。绘图时由模型按画格可见范围选取，不强行拼接整份记忆。

已有简略外貌不会自动重写。更新 SDT 6.2.3 与角色工坊 2.2.27 后，可在对应角色卡聊天中点击「从角色卡提取 / 更新外貌」：成功才替换外貌，保留已有当前服装与衣柜，并在 `previousBaseTags` 保存最近一次被替换的外貌（目前无恢复按钮）。默认服装仅在新建档案或原服装为空时填入。失败会提示错误，禁止将角色卡原文直接当作标签保存；工坊不会因提取失败而重置未保存的草稿。

上述规格不增加漫画 Tagger 请求次数，不引入七维强制校验或规划重试；实际标签完整度与画质仍依赖模型，需真实出图核对。

SDT 6.2.2 恢复漫画模式的新角色建档和衣着更新。开启 SDT 的角色外貌记忆后，同一次 Tagger 响应增加简短的 `character_memory` 数组，每人一项 `{name, base, outfit}`。资料使用原有的聊天独立角色档案和衣柜，新角色会出现在原有角色列表中。

- `name` 与格内人物的稳定姓名对应；同一人物跨格跨页只学习一次，C1、P1、空镜和匿名路人不建档。
- `base` 用于新建外貌或填补空档案。已有非空外貌保持原值；模型根据资料为每格选取可见特征，程序不把整份档案强塞回特写。
- `outfit` 仅在首次着装或明确变化时提交完整已知衣着，空字符串保留已有着装。提示词要求使用本楼最后出场时的状态，不把裁切视野当作换装。不同服装沿用原有衣柜归档逻辑。
- 外貌资料与漫画画风分别处理，黑白画面仍可保存已知发色、瞳色供后续复用。资料不从混有动作、气泡和对白的 `positive` 自动拆取；带 `Text/BubbleType/Layout/SFX` 的记忆字段会被跳过。
- 页格全部解析成功后才写记忆。重新解析较旧楼层时，不覆盖漫画模式已记录的较新楼层着装。模型仍需正确区分完整着装与局部可见衣物，程序无法判断所有标签的语义。

仅在记忆开关开启时增加该输出要求，没有额外请求或自动重试。模型漏返回记忆资料时保留有效漫画页、跳过这次学习，可在原始输出中检查 `character_memory`。已缓存的旧漫画需重新解析才会建档，直接重绘不会重新学习。

## 本楼剧情如何变成漫画

SDT 在同一次 Tagger 请求中先规划、后填写绘图词：

1. **承接状态**：历史只提供进入本楼时仍有效的身份、场所、衣着、持物和接触状态。本楼发生的变化按顺序更新，后文的换装不会提前应用到前面的格；角色档案和衣柜不能覆盖已经发生的变化。自动解析只传入目标楼层之前的历史，避免重解析旧楼时混入后续剧情。
2. **选择剧情**：扫描本楼开端到结尾，选择登场、重要动作与结果、关键对白、情绪变化、线索和转场。重复的小动作可以合并；没有新信息的寒暄、纯抽象议论和未发生的假设不需要硬画。没有大动作的告白、拒绝等关键对白仍然可以画。
3. **安排页格**：每个 `segment` 是一张最终图片。先安排画格，再按动作、人数、文字容量和叙事停顿组合成页。普通页 2～5 格仅作容量参考，单格页合法；长对白和复杂互动可跨页。普通插画的“最少分镜数”和 `[图组]` 标记数量不再强制决定漫画页数。
4. **确定每页内容**：每页可用 `intent` 简述主画面、叙事任务和分页理由；各格指定阅读位置、景别、一个相容的定格时刻、可见人物与对白。文法作为演出偏好，不为热血风格强加斜切格，不为四格编造剧情。

### 1.6.1：减轻解析负担

取消 1.6.0 的强制 `story_plan`、逐字 `source`、`beat_ids` 覆盖报告及整次规划修正重试。模型直接提交最终页格，不再因节点引用有标点/措辞差异或排序差异而报“漫画规划校验失败”。收到旧版附带的节点清单时也不以它阻断有效漫画页。

保留前情承接、剧情选择、分页和对白规则，将前情增强缩为简短指令。`intent` 为可选的一句话说明，缺失不报错；可在现有卡片调试详情中查看。页数按实际 `segments` 数量计算。

程序仍检查可渲染的页面结构、人物数据及有效坐标，避免把损坏数据传给绘图模型。引用措辞变化交给现有锚点定位逻辑处理，不触发额外 Tagger 请求。本次移除的是漫画规划重试，接口原有的格式兼容/流式降级逻辑保持不变。

最终选材、对白可读性和画质仍需用实际 Tagger/绘图模型做对照；本次没有测量真实接口延迟。

## 这一版改变了什么

漫画使用“页面 → 画格 → 格内人物”结构。同一格可以有多人，一个人可以跨格多次出场；空镜不创建人物槽。画格数与人物出场槽数分别计算。

聊天自动解析、手动描述生图、工具调用及漫画工作台共用漫画协议。逐人物正负词在最后发送时展平成 NAI `char_captions`，不再通过“一个画格等于一个角色”组织请求。

- 页面及画格的环境、旁白、拟音、画外对白进入全局 caption；可见人物的动作和对白进入本人 caption。
- 各字段的视觉说明排列在 `Text:` 之前，台词和多气泡空行保留，外层对白引号按原预设剥除。台词里的逗号、竖线和 `no text` 不参与标签清理。
- 分页依据事件、文字量和画格容量，允许单格大画面。经典四格保留均等画格，不再与全局“禁止四等分”指令冲突。
- 角色记忆和世界书是导演的资料输入；1.7.0 起，新页按可见部位补入记忆，避免整份全身档案覆盖局部镜头。
- 负面清理以完整标签及闭合权重块为单位。原作排除词由导演根据资料明确填写，不从任意括号猜测作品名。
- 请求顶层 `model` 设为 `nai-diffusion-5-full`。横向跨页只检测视觉描述，不检测台词。
- **Prompt Presets 插件的画风拼接保持现有行为。**

## 使用

在 SDT 的提示词设置中开启漫画模式，或直接进入独立的“漫画工作台”。关闭漫画模式时会恢复启用前的 SDT 提示词、自定义预设、前情分析及多角色设置。

工作台支持 1～5 格：

1. 输入剧情后使用“AI 智能分镜推演”，或逐格输入剧情后批量解析。
2. 设置各格的位置、大小、景别与环境。
3. 展开“格内人物与文字”，分别编辑每个人的身份编号、姓名、镜头描述、对白及负面词。同一人物跨格使用相同身份编号。
4. 旁白、拟音和画外文字放在单独的非人物文字栏；空镜保留零个人物。
5. 检查组装预览后生成。静默格与有对白的格子使用同一组装流程。

工作台 AI 使用 SDT 的 OpenAI 兼容接口配置。接口未配置、调用失败、JSON 无效或格数不符时保留当前分镜并提示错误，不再用猜测剧情自动替代。经典四格须选择自动或 4 格。

格子的增删、复制或移动会重新安排默认位置，之后可手动调整位置和大小。人物编辑区按需展开，支持手机端纵向编辑。

## 数据协议

每个 SDT `segments[]` 是一个漫画页：

```json
{
  "format": "nai5-comic",
  "label": "Page 1: 放学后",
  "intent": "两人约定同行，以对话为主格、离开后的空教室收尾，同页完成。",
  "anchor": { "text": "她们交谈后转身离开了教室。" },
  "page": { "base": "comic, 2 panels, 2girls, vertical layout" },
  "panels": [
    {
      "id": "P1",
      "description": "top panel, classroom, medium shot",
      "characters": [
        { "character_id": "C1", "name": "甲", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, long hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 一起回家吧。", "negative": "short hair" },
        { "character_id": "C2", "name": "乙", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, short hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 好。", "negative": "long hair" }
      ]
    },
    {
      "id": "P2",
      "description": "bottom panel, empty classroom",
      "non_character": "bottom panel, SFX: 擬音, 吹き出しなし, Text: 咔哒",
      "characters": []
    }
  ]
}
```

默认自动定位。导入的手动定位页可用 `position_mode: "manual"`，每次人物出场需填写有效 `center: {x, y}`（0～1）。编译器检查画格 ID、同格重复人物、正负词字段及手动坐标。

上例是单页结构；SDT 顶层响应为 `{ "shouldDraw": true, "segments": [...] }`，可附简短 `reason`。无需节点清单或原文覆盖报告。文本 JSON 与工具调用使用相同页格结构。

## 已有数据

不会自动删除或改写已保存的分镜、模板或角色档案。旧版工作台混合标签保留为页面内容，不猜测人物身份；点击“AI 润色本格”或批量解析后转换为新结构。新版内置模板已明确拆分人物与环境。

SDT 已缓存的旧分镜继续使用旧数据重绘；重新解析时要求新协议。漫画页换装通过 AI 微调按人物出场更新，避免字符串拼接同时保留新旧衣服。
