# 漫画模式与漫画工作台

插件 ID：`rbq-manga-mode`。入口：[manga-mode.js](../../plugins/manga-mode.js)。

版本：**1.9.0**，配套智能生图（SDT）**6.5.0**。两个插件需要配套更新并刷新酒馆。宿主 **0.3.110** 增加每次生图请求的上下文传递；旧宿主兼容路径串行提交 SDT 生图。

## 1.9.0 / SDT 6.5.0：同一次解析输出灰阶绘图视图

仅漫画专属画风选择 **黑白** 时启用。参考原版 `v1.1.json` 的「色彩-黑白脱色」整页规则，由同一次 Tagger 解析处理人物、道具、环境、文字视觉说明和光照。发送层移除颜色词表替换，只组装画风、逐格快照与文字；普通模式、柔彩漫画、自定义画风保留原来的完整原色资料与绘图路径。

- 普通角色记忆仍使用 `base/outfit/state`，保存姓名、同人 Tag、国籍、年龄、身高、固有颜色、完整外貌、衣物层次和配饰。
- 黑白解析首次出场额外输出 `render:{base,outfit}`，是该时刻的完整灰阶外貌与衣着。后续格/页省略未变化的成员；程序根据原色来源复用对应灰阶视图，重复生成另一套视图也不会让同一外观漂移。
- 明确换装只更新 `render.outfit`，临时外貌变化只更新 `render.base`；两者都变则一起更新。每个视图绑定其当前完整原色来源，防止后面变化继续套用旧服装/外貌。清空衣着同时清空灰阶衣着。
- 绘图编译只用灰阶视图和本格演出；长期档案、衣柜、前后状态历史只用原色数据。关闭长期记忆仍可在本次响应内延续灰阶视图，不创建档案。没有增加模型调用、重试、外貌裁剪、姓名删除或双语删减。
- 解析时保存所选画风设置，缓存和重绘使用已编译快照；之后修改档案或切换画风不会混入另一份设置。手动编辑清除隐藏的原色/灰阶字段，工作台使用平铺快照，AI 润色同样支持灰阶视图且不更新长期记忆。

新黑白解析若缺少首次/变化后的必要视图，会定位到具体 `render.base` 或 `render.outfit`，在记忆落库前结束；不猜颜色、不悄悄发送原色、不自动追加模型请求。旧缓存完整提示词继续可重绘，但不会再被词表重写；需 **重新解析** 才能得到新灰阶视图。切换黑白与彩色后也应重新解析，再评价本次画风效果。Prompt Presets 的画风拼接未改动。

验证：23 项新增灰阶测试、107 项漫画回归、15 项跨入口审计，以及原预设/宿主对照和普通情境检查。新增测试覆盖原色与灰阶隔离、跨页继承、换装、临时外貌、清空、匿名角色、姓名及权重、缓存重绘、两种钩子顺序、手动编辑、SDT/工作台润色、自定义 HTTP/OpenAI JSON/工具调用的单次请求。测试执行真实程序函数，模型回复为夹具；未调用真实 Tagger 或生图服务，不能保证模型每次都遵循灰阶要求或实际位图完全没有颜色。

## 1.8.5 / SDT 6.4.4：按实际测试补齐黑白与分页信息

用户用 1.8.4 / 6.4.3 测试了选材、递信动作和长对白，分别单独解析及合并成一楼解析。主辅格与并排布局已经出现；合并三页的角色外貌衣着词一致。单独解析的不同外貌属于本次测试方式，不作为缺陷。用户确认少量补对白、接触瞬间偏差可接受，本轮不追加对此的严格限制或校验器。

- 黑白最终请求的转换补齐米色、奶油色等常见中性色，以及风衣、牛仔裤、针织衫、百褶裙表达。`warm/cool indoor lighting` 去掉色温指示，保留环境与阴影描述；角色姓名、原句文字、长期记忆保持原色。
- 正文解析、自定义 HTTP、手动描述和生图测试的漫画请求附带 `mangaCanvas`（当前所选宽高、方向与智能跨页选项）。工作台使用自己的比例。普通模式不附带这些字段，不改图片尺寸或参数。
- 前情规划根据画布空间分配文字与动作，长对白可按已有停顿分泡、跨格或跨页；保留关键条件、理由和句尾，不按固定字数删除。没有增加请求次数或机械拆页。

六张测试 PNG 的实际提示词经新发送钩子离线重放，确认的颜色漏词转为灰阶，人物槽、台词、种子与步数保留。107 项漫画回归、15 项跨入口审计、6 项原预设/宿主对照通过。未重新调用真实模型；提示词转换有效不等于实际图片必定完全黑白，也不能证明新规划不再漏掉对白。详细样本结论见 [画面质量检查](rbq-manga-quality-2026-10-04.md)。

## 1.8.4：旧结果的连续气泡文字兼容

旧结果可能在真实台词之后的独立段落中再次写入 `BubbleType: …, Layout: …, Text: …`，导致格式标记被画成文字。现在仅识别段首明确的已知气泡/拟音协议，把格式移到最终 `Text:` 前，保留各句次序、标点及双语内容。不猜测说话者，不移动文字到其他人物槽，不改写行内提及或引用的协议示例。

连续气泡可能使用相同类型、位置和排版。这些重复字段不再按普通视觉标签去重，避免第二泡失去对应格式。修复用于新页编译及旧缓存发送、重绘，角色记忆、画风预设和生图参数不变，没有额外模型调用。

验证：105 项漫画回归、15 项跨入口审计、6 项原预设/宿主对照通过。检查的是最终提示词与请求；未调用真实生图，不能据此声称实际布局、动作与文字质量已经达标。旧图片不用于判断最新版效果。普通剧情样本的具体问题见 [画面质量检查](rbq-manga-quality-2026-10-04.md)。

## 1.8.3 / SDT 6.4.3：全链路对照与请求隔离

对照实际 `v1.1.json` 的提示词和“漫画台 v1.1”内嵌编译器，检查选材分页、版面、人物、动作、文字、画风、最终请求、编辑与重绘。完整结论见 [本轮检查记录](rbq-manga-audit-2026-10-04-final.md)。

- 身份匹配键与绘图姓名分开：原创 `(original)` 后缀保留，同人姓名权重在普通模式首次/复用与漫画模式一致。`name` 携带完整身份，程序补入绘图外貌，不要求模型重复填名；已有丰富身份标签保留。跨格遗漏姓名时仅按无歧义的 `character_id` 承接。
- 首次参考选项在关闭长期记忆时仍提供角色卡和附带世界书；群聊只参考本群成员。普通模式与漫画继续共用完整 base/outfit 记忆。
- 所有 SDT 生图入口及漫画工作台使用独立的人物、负面词、画风与坐标快照。宿主在排队和参考图预处理后把该请求上下文交给载荷钩子，避免人物串到另一张图。解析预览不再留下待注入的全局人物数据。
- 手动负面词与显式空字符串贯通卡片、序列化、抽屉和最终请求。编辑结果同时保存到 SDT 缓存与 `message.extra`，再次重绘和刷新不恢复旧词。工作台平铺快照清除旧隐藏状态；在途漫画 AI 润色遇到聊天或模式切换停止回填。
- 两套原始画风库与原版一致（仅排版空白不同）；黑白库撤回额外加入的 `3D/realistic photo`。漫画请求沿用原脚本的 `qualityToggle=false`、`ucPreset=3`，保留宿主选定的模型、采样器、步数和种子。非人物文字字段错误类型会显示字段诊断。

验证：102 项漫画回归、15 项跨入口审计、6 项实际原预设/宿主对照通过；17 个普通情境的 289 项断言和 15 项提示词静态检查通过。没有调用真实 Tagger 或生图服务，测试不能证明每次模型选材、动作或文字都正确。

本轮保留单次解析、自适应页数、主辅格面积与排列要求、原句文字归属，以及用户要求的完整姓名/国籍/年龄/身高记忆。没有恢复固定六页、长篇逐句规划、额外模型重试或中文双语删减规则；Prompt Presets 文件未修改。

## 1.8.2 / SDT 6.4.2：补回漏掉的角色姓名标签

修复截图所示“角色名存在于编辑器标题，Base Tags 却只有外貌”的问题。普通首次建档原本会拼入 name，漫画建档与角色卡提取却直接保存模型 base；上一轮对照用例使用已经含姓名的档案，未覆盖首次漏名。

- 普通首次建档、漫画外貌解析和角色卡提取共用 `ensureCharacterNameTag`，在已有外貌词前补入可靠的现有姓名。已存在的同名词（含单词权重或下划线形式）不重复追加，不因短名字是另一名字的子串而误判。
- 漫画正常解析时，对缺姓名的既有非空档案只追加姓名，保留原外貌；不以本次模型重写的外貌替换旧档案。临时外貌也保留姓名；这类补名不会让原临时状态的来源校验失效。
- 匿名路人、C1 等编号不作为姓名 Tag 注入，不给未知外貌创建只有姓名的漫画档案。手动编辑和旧缓存编译仍保留用户最终词，不在重绘时擅自改回。
- 共享提取指令和漫画 Schema 明确要求已识别的同人角色将可靠通用角色 Tag 写入 base，不能只放在 name。程序仅能补现有姓名，不把中文显示名自动猜成英文角色 Tag 或虚构作品限定；已有可靠 Tag 原样保留。

验证：**102 项漫画回归**通过。新增用例先在旧代码上复现首次漏名，再验证普通/漫画首次建档对照、既有档案补名、同名去重、匿名排除、同人 Tag 跨状态与黑白发送保留；现有角色卡提取用例也改为检查最终姓名。未调用真实提取模型或生图服务。

更新两个插件后重新解析可补回已知姓名。截图中已建档但缺可靠同人 Tag 的角色，可使用“从角色卡提取/更新外貌”按新指令重新提取；仅点重绘不会重建已有资料。

## 1.8.1 / SDT 6.4.1：补齐完整记忆在各入口的衔接

本轮沿角色卡参考、模型输出、逐格合并、记忆保存、手动编辑、AI 润色与重绘检查，修复以下问题：

- 角色卡参考和衣柜附加指令残留旧的“可见特征写入 positive”规则。统一为完整 base/outfit，positive 仅表示本格演出；明确兼容 character_memory 的末格 outfit 与各格当前 outfit 不同。
- 关闭长期记忆曾同时跳过本次漫画的状态延续。现在仍处理本次响应内的换装和临时外貌，但不读取或写入长期记忆。未具名角色也按 character_id 延续；同名“路人”按各自编号隔离。
- 空的兼容 character_memory 行不再阻止直接从格内 base 建档。缺少开场衣着的资料，只能由首次出场的 outfit 补足，不能倒用后面换装；已知开场衣着保留。
- 完整临时外貌记录其来源 base。明确修正长期外貌后，旧来源的临时快照不再覆盖新资料；已生成页的缓存不变。旧记录若没有来源信息，无法可靠判断是否已经过修正，重新解析对应楼层可建立新记录。
- 新协议只提供完整 state.base/state.outfit，不再引导模型输出已停用分类合并的独立发型字段；旧记录的发型字段仍可读取。
- base/outfit/name 和 state 的类型在全部页面编译前检查，防止数组或对象变成绘图词，也防止非法后格导致前格记忆部分落库。旧缓存未带 base/outfit 时仍兼容。
- 工作台及 SDT 的 AI 润色统一处理返回的逐格状态，使用草稿资料，不重新套聊天默认衣着，也不保存长期记忆。
- 手动修改完整人物词时同步清除隐藏的旧 base/outfit/state，避免后续编译重复拼接或恢复已删除的标签。

验证：**96 项漫画回归**通过，覆盖普通模式合并对照、角色卡、自定义 HTTP/工具调用、无记忆状态延续、匿名人物隔离、新角色建档、历史状态、手动编辑、AI 润色及重绘。另通过 17 个既有情境的 289 项断言、15 项提示词检查，以及脚本语法、插件清单与差异检查。未调用真实模型或生图服务，实际画面与速度仍需更新后实测。本次未增加模型调用，不改 Prompt Presets 拼接、分页布局偏好或对白语言规则。

## 1.8.0 / SDT 6.4.0：共用普通模式的完整角色记忆

按用户要求撤掉漫画专用的七部位分类组装。此前围绕裁切、同义词和服装类别不断扩展规则，仍会误删合法叠穿；本版不再扩充分类器。

- 普通模式与漫画共用 `resolveCharacterMemoryFields`：已建档使用原有完整 base，outfit 无更新时沿用，有明确更新时使用完整新衣着。共用同一聊天角色档案、衣柜、角色卡读取和资料更新入口。
- 格内人物使用 name/base/outfit/positive。base 与 outfit 不按特写、背面或可见部位裁剪；positive 负责该格位置、动作、表情和对白。姓名、国籍、年龄、身高、自定义标签与叠穿保留资料原文。
- 删除部位分类、外貌同义词改写及按 visible 删词的流程，新请求不要求 visible。衣物由模型输出完整 outfit，不由程序猜测衬衫、马甲或配饰是否冲突。
- 逐格换装按发生顺序延续，末格衣着不覆盖前格。明确临时外貌变化用完整 state.base 快照表达，仅用于剧情状态，不覆盖长期 base；镜头裁切不属于外貌变化。
- 新人物可以直接从格内 base/outfit 建档，不强制额外 character_memory 数组；该数组作为可选兼容字段保留。全部页格结构检查完成后才保存，避免部分失败污染资料。
- 旧缓存的完整 positive 原样兼容，不尝试拆标签；重新解析可使用新合并逻辑。工作台 AI 使用同样字段，编辑器保留合并后的完整快照，避免隐藏资料在编辑后重新覆盖。
- 黑白转换仍在最终请求层处理，长期资料保留原色。保留 1.7.4 对所选生图模型的尊重，布局、文字规则及 Prompt Presets 拼接不变，未新增模型请求。

验证：**87 项漫画回归**通过，包括调用普通模式真实合并函数与漫画路径对照完整资料、衬衫加马甲叠穿、自定义标签、特写不删记忆、无额外元数据建档、逐格状态、跨楼回滚、工作台及旧缓存。17 个情境场景的 289 项断言、15 项既有提示词检查通过。原先要求“裁切必须删除标签”的测试改为完整资料保留契约。未调用真实生图服务；更新两个插件后须重新解析正文才能应用新协议。

## 1.7.4：移除强制改写 NAI V5 模型的限制

去除了生成请求时强制将顶层 `model` 设为 `nai-diffusion-5-full` 的硬编码逻辑。漫画模式完全尊重并保留用户在酒馆/SDT中选定的生图模型（如 NAI V4.5、V4 Curated、V3 等），不再强制切换为 NAI V5。

## 1.7.3 / SDT 6.3.2：恢复具体布局要求，修复状态与外貌组装

依据 [原版内嵌脚本与规划流程补查](rbq-manga-v1.1-runtime-review.md)，保留单次请求与自适应分页，恢复原版对最终页面布局的具体要求。

- **选材、分页与布局**：前情规划要求先选本页主事件，再将剩余事件分配到辅助格；最终 page.base 明确主格位置及大致面积、辅助格大小与邻接排列、阅读路径。相同位置称呼贯穿格内描述和人物。全宽横格仍合法，经典四格仍可等分，不随机切模板、不强制斜切、不固定六页。
- **人物外貌**：模型按原版方式写完整的镜头可见外貌与动作，程序只补全和校正可识别部位。补齐 updo style、voluptuous body、lipstick、hair pin、keyhole cutout、side slit 等实际样例。未知自定义细节在局部镜头跟随模型选择，全身镜头保留；长期记忆不因裁切而删词，普通姓名、国籍、年龄与身高仍保留。
- **衣物与配饰**：按衣物部件判断冲突，衬衫不再清掉眼镜和项链。明确换装后清除上一套衣物，包括已被模型转成灰阶的旧衣物；持续状态不提前作用于前格。
- **跨楼状态**：并发保护改为比较请求开始时的真实档案衣着，同楼重新解析不再误判为手动换装。新增状态记录带正文/回复分支版本；下次读取时，改写、切换或删除的楼层及其后续状态失效。shouldDraw=false 的成功重解析也清除该楼及后续旧状态。失效处理保留长期外貌、衣柜条目及独立手动衣着选择；旧版本没有正文版本的记录不能可靠追溯，需重新解析对应楼层。
- **黑白处理**：模型负责全页灰阶转译，持久资料保留原色；程序对页面、人物、道具和环境中已识别的颜色短语统一补处理，包括 red pen、red lipstick、brown wooden desk。准确姓名单独保护，Text 原文不改。任意自然语言颜色表达仍需模型正确转译。
- **轻量诊断**：数字或英文数字的明确 panel 数量按实际数组修正；页面/格内描述误放 Text、非人物字段出现疑似人物气泡时附诊断。保留内容，不猜说话者，不触发二次模型请求。非人物文字合并仍沿用原脚本。

## 1.6.2：文字格式与通用动作表达

对照原预设 v1.1.json 的「气泡:边框形状」「文字:演出契约」和「语法:输出协议」，沿用原文字格式：视觉标签、气泡类型、位置和 Layout 写在前面，末尾只用一个 Text:，后面只放实际原句。同人多句用空行分隔，不复制人物槽。示例：

```text
top panel, girl, holding envelope, BubbleType: 通常吹き出し, 右上, Layout: 縦書き
Text: 信收到了。

谢谢。
```

本地文字整理会修复明确的错误结构，例如 `Text: 通常吹き出し, Layout: 縦書き, Text: 信收到了。`，把格式头移到台词前；去除独立整句外包的「」或引号。句内真实引用和普通台词中出现的 Text/Layout 等字样保留。整理作用于页面编译及发送前，因此已缓存的格式错误也可在重绘时修复；缺失的台词不会被程序编造，须重新解析或手动补充。

提示词明确区分可见人物对白、画外声、旁白和拟音。需要上画的文字实际写进 Text，不能只写 speaking/speech bubble；静默格不要求空白气泡。模型对文字归属和漏字的判断仍需实际出图核对。

参考 v23、v24、v40 的通用标签规则，绘图字段要求以英文逗号分隔的标签为主；人物按位置、可见外貌衣着、基础姿势、肢体及接触对象、表情视线组织。自然语言仅用于紧邻标签的短关系补充。新增递信的非露骨动作示例，约束多人物动作归属、可见性、互斥姿势和闭合短词组权重。没有恢复旧预设的固定页数、每页标签配额或额外分析请求。

已有简略外貌不会自动重写。更新 SDT 6.2.3 与角色工坊 2.2.27 后，可在对应角色卡聊天中点击「从角色卡提取 / 更新外貌」：成功才替换外貌，保留已有当前服装与衣柜，并在 `previousBaseTags` 保存最近一次被替换的外貌（目前无恢复按钮）。默认服装仅在新建档案或原服装为空时填入。失败会提示错误，禁止将角色卡原文直接当作标签保存；工坊不会因提取失败而重置未保存的草稿。

上述规格不增加漫画 Tagger 请求次数，不引入七维强制校验或规划重试；实际标签完整度与画质仍依赖模型，需真实出图核对。

SDT 6.2.2 恢复漫画模式的新角色建档和衣着更新。开启 SDT 的角色外貌记忆后，同一次 Tagger 响应增加简短的 `character_memory` 数组，每人一项 `{name, base, outfit}`。资料使用原有的聊天独立角色档案和衣柜，新角色会出现在原有角色列表中。

- `name` 与格内人物的稳定姓名对应；同一人物跨格跨页只学习一次，C1、P1、空镜和匿名路人不建档。
- `base` 用于新建外貌或填补空档案。已有非空外貌保持原值；模型根据资料为每格选取可见特征，程序不把整份档案强塞回特写。
- `outfit` 仅在首次着装或明确变化时提交完整已知衣着，空字符串保留已有着装。提示词要求使用本楼最后出场时的状态，不把裁切视野当作换装。不同服装沿用原有衣柜归档逻辑。
- 外貌资料与漫画画风分别处理，黑白画面仍可保存已知发色、瞳色供后续复用。资料不从混有动作、气泡和对白的 `positive` 自动拆取；带 `Text/BubbleType/Layout/SFX` 的记忆字段会被跳过。
- 页格全部解析成功后才写记忆。重新解析较旧楼层时，不覆盖漫画模式已记录的较新楼层着装。模型仍需正确区分完整着装与局部可见衣物，程序无法判断所有标签的语义。

仅在记忆开关开启时增加该输出要求，没有额外请求或自动重试。模型漏返回记忆资料时保留有效漫画页、跳过这次学习，可在原始输出中检查 `character_memory`。已缓存的旧漫画需重新解析才会建档，直接重绘不会重新学习。

## 本楼剧情如何变成漫画

SDT 在同一次 Tagger 请求中先规划、后填写绘图词：

1. **承接状态**：历史只提供进入本楼时仍有效的身份、场所、衣着、持物和接触状态。本楼发生的变化按顺序更新，后文的换装不会提前应用到前面的格；角色档案和衣柜不能覆盖已经发生的变化。自动解析只传入目标楼层之前的历史，避免重解析旧楼时混入后续剧情。
2. **选择剧情**：扫描本楼开端到结尾，选择登场、重要动作与结果、关键对白、情绪变化、线索和转场。重复的小动作可以合并；没有新信息的寒暄、纯抽象议论和未发生的假设不需要硬画。没有大动作的告白、拒绝等关键对白仍然可以画。
3. **安排页格**：每个 `segment` 是一张最终图片。先安排画格，再按动作、人数、文字容量和叙事停顿组合成页。普通页 2～5 格仅作容量参考，单格页合法；长对白和复杂互动可跨页。普通插画的“最少分镜数”和 `[图组]` 标记数量不再强制决定漫画页数。
4. **确定每页内容**：每页可用 `intent` 简述主画面、叙事任务和分页理由；各格指定阅读位置、景别、一个相容的定格时刻、可见人物与对白。文法作为演出偏好，不为热血风格强加斜切格，不为四格编造剧情。

### 1.6.1：减轻解析负担

取消 1.6.0 的强制 `story_plan`、逐字 `source`、`beat_ids` 覆盖报告及整次规划修正重试。模型直接提交最终页格，不再因节点引用有标点/措辞差异或排序差异而报“漫画规划校验失败”。收到旧版附带的节点清单时也不以它阻断有效漫画页。

保留前情承接、剧情选择、分页和对白规则，将前情增强缩为简短指令。`intent` 为可选的一句话说明，缺失不报错；可在现有卡片调试详情中查看。页数按实际 `segments` 数量计算。

程序仍检查可渲染的页面结构、人物数据及有效坐标，避免把损坏数据传给绘图模型。引用措辞变化交给现有锚点定位逻辑处理，不触发额外 Tagger 请求。本次移除的是漫画规划重试，接口原有的格式兼容/流式降级逻辑保持不变。

最终选材、对白可读性和画质仍需用实际 Tagger/绘图模型做对照；本次没有测量真实接口延迟。

## 这一版改变了什么

漫画使用“页面 → 画格 → 格内人物”结构。同一格可以有多人，一个人可以跨格多次出场；空镜不创建人物槽。画格数与人物出场槽数分别计算。

聊天自动解析、手动描述生图、工具调用及漫画工作台共用漫画协议。逐人物正负词在最后发送时展平成 NAI `char_captions`，不再通过“一个画格等于一个角色”组织请求。

- 页面及画格的环境、旁白、拟音、画外对白进入全局 caption；可见人物的动作和对白进入本人 caption。
- 各字段的视觉说明排列在 `Text:` 之前，台词和多气泡空行保留，外层对白引号按原预设剥除。台词里的逗号、竖线和 `no text` 不参与标签清理。
- 分页依据事件、文字量和画格容量，允许单格大画面。经典四格保留均等画格，不再与全局“禁止四等分”指令冲突。
- 角色记忆和世界书是导演的资料输入；1.7.0 起，新页按可见部位补入记忆，避免整份全身档案覆盖局部镜头。
- 负面清理以完整标签及闭合权重块为单位。原作排除词由导演根据资料明确填写，不从任意括号猜测作品名。
- 不再强制覆盖请求顶层的绘图模型（保留用户在酒馆/SDT中选定的生图模型）。横向跨页只检测视觉描述，不检测台词。
- **Prompt Presets 插件的画风拼接保持现有行为。**

## 使用

在 SDT 的提示词设置中开启漫画模式，或直接进入独立的“漫画工作台”。关闭漫画模式时会恢复启用前的 SDT 提示词、自定义预设、前情分析及多角色设置。

工作台支持 1～5 格：

1. 输入剧情后使用“AI 智能分镜推演”，或逐格输入剧情后批量解析。
2. 设置各格的位置、大小、景别与环境。
3. 展开“格内人物与文字”，分别编辑每个人的身份编号、姓名、镜头描述、对白及负面词。同一人物跨格使用相同身份编号。
4. 旁白、拟音和画外文字放在单独的非人物文字栏；空镜保留零个人物。
5. 检查组装预览后生成。静默格与有对白的格子使用同一组装流程。

工作台 AI 使用 SDT 的 OpenAI 兼容接口配置。接口未配置、调用失败、JSON 无效或格数不符时保留当前分镜并提示错误，不再用猜测剧情自动替代。经典四格须选择自动或 4 格。

格子的增删、复制或移动会重新安排默认位置，之后可手动调整位置和大小。人物编辑区按需展开，支持手机端纵向编辑。

## 数据协议

每个 SDT `segments[]` 是一个漫画页：

```json
{
  "format": "nai5-comic",
  "label": "Page 1: 放学后",
  "intent": "两人约定同行，以对话为主格、离开后的空教室收尾，同页完成。",
  "anchor": { "text": "她们交谈后转身离开了教室。" },
  "page": { "base": "comic, 2 panels, 2girls, vertical layout" },
  "panels": [
    {
      "id": "P1",
      "description": "top panel, classroom, medium shot",
      "characters": [
        { "character_id": "C1", "name": "甲", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, long hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 一起回家吧。", "negative": "short hair" },
        { "character_id": "C2", "name": "乙", "visible": ["hair", "face", "eyes", "torso"], "positive": "top panel, girl, short hair, BubbleType: 通常吹き出し, Layout: 縦書き, Text: 好。", "negative": "long hair" }
      ]
    },
    {
      "id": "P2",
      "description": "bottom panel, empty classroom",
      "non_character": "bottom panel, SFX: 擬音, 吹き出しなし, Text: 咔哒",
      "characters": []
    }
  ]
}
```

默认自动定位。导入的手动定位页可用 `position_mode: "manual"`，每次人物出场需填写有效 `center: {x, y}`（0～1）。编译器检查画格 ID、同格重复人物、正负词字段及手动坐标。

上例是单页结构；SDT 顶层响应为 `{ "shouldDraw": true, "segments": [...] }`，可附简短 `reason`。无需节点清单或原文覆盖报告。文本 JSON 与工具调用使用相同页格结构。

## 已有数据

不会自动删除或改写已保存的分镜、模板或角色档案。旧版工作台混合标签保留为页面内容，不猜测人物身份；点击“AI 润色本格”或批量解析后转换为新结构。新版内置模板已明确拆分人物与环境。

SDT 已缓存的旧分镜继续使用旧数据重绘；重新解析时要求新协议。漫画页换装通过 AI 微调按人物出场更新，避免字符串拼接同时保留新旧衣服。
